# 运行时交互审计与反思决策缺口

时间：2026-10-28，Asia/Shanghai。检查基线为 1.6.0，交互边界修订为 1.6.1。未运行分子实验、LLM 评测或远端部署，未改变自动化。

## 实际发现与已修改内容

- `references/preference-elicitation.md` 原文包含“or an uncovered tradeoff materially affects a decision”，会让主 GPT 把运行时未覆盖取舍当成提问触发器。现限定为用户主动发起的独立设计会话。
- `references/decision-boundaries.md` 原文为“the supervisor handles policy questions”；只排除了推理 Agent 的人类提问工具，没有禁止主 GPT 间接询问。现对两者共同禁止运行时人类交互。
- 主技能原文仅说推理 Agent 不应假定有提问工具，强度不足。共享 runtime 段和四份 distance 技能现在明确不提问、不联系、不发问答/审批卡、不等待/轮询用户回复。
- `confirmed-search-policy.md` 中的 supervisor intervention 改为机器控制器记录及依赖操作的停止路径。`history-memory-contract.md` 明确自动记忆审查同样不开展访谈。
- 此前偏好本身保留，访谈资料作为维护资源保留。问题清单和论文不塞进常规推理 prompt。未改变冻结的实验 skills。
- 对 `geometry_council.py`、`geometry_runtime.py` 的定向检查没有发现 `input(`、`request_user`、`ask_user`、`human_feedback` 调用匹配；这是这些文件的检查结果，不是整个宿主工具权限已被硬隔离的证明。

## 新交互边界

运行时：执行已确认规则；需要事实时通过支持的机器接口查找。缺少关键规则/阈值/接口时，使用已有不确定性或复盘字段记录，禁止执行依赖该缺失项的无依据操作；独立操作只在原协议允许时继续。不得捏造新 skip 字段、空候选或用户答复依赖。

设计时：用户明确要求访谈才提问。答案与来源、适用条件、例外及代码能力分开记录，随后写成直接指引。推荐未获确认前停留在本设计目录，不作为运行时缺省。

这是 skills 层规则，未新增运行时失败接口、审批系统或工具沙箱。缺少接口的现有执行器不能被描述成已支持自主 abstention。

## 仍需当前用户决策的六项

1. 局部经验进入固定指引的范围和门槛。
2. 相互冲突的经验出现时，优先辨别原因还是继续局部收益。
3. 没有新增证据时是否允许不改 skills；现有每次一至三个模块规则可能强迫无价值修改。
4. 一个主要假设的小范围修订、联合修订和分离候选的取舍。
5. 流程改进与科学收益不一致时的新 skills 采用规则。
6. 跨教师迁移方法、迁移待验证假设或等待各自实证的边界。

详见 questions.zh-CN.md 与 interview.json。所有情景为设计推演，不是声称观察到了新的实验数据。

## 不应再次交给用户选择的事实与约束

先核对输出动作是否被正确执行、历史是否送达、测量是否有效，再评价解释。模型解释不能覆盖实测、重复调用不能增加独立证据、没有测量不能补成数值。风险优先、已确认回滚、固定样本结论边界、教师独立标定及原预算继续有效。不能把这些硬约束变成投票选项。

## 后续采纳办法

每项确认后形成“证据条件 → 直接行动 → 适用范围 → 反例/修订条件”的短规则，映射到 analysis/proposal/synthesis 或主 GPT review。保留固定输出模块和字段；兼容性/执行权限仍由代码验证。若选项改变 review 验收（如零修改）、候选比较或先验通道，需明确代码集成状态，不能只改文字就宣称具备执行能力。
