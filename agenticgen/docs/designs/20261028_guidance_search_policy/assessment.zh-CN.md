# Guidance Agent 决策缺口与第二轮偏好访谈

日期：2026-10-28，Asia/Shanghai。核查基线：`c300ed49`，skills 1.2.0。本文记录论文机制、当前代码能力与需要用户选择的取舍；模拟情景不是新实验结果。原有 `condition-preservation-design-v1` 优先级继续有效。

## 结论

当前 skills 已说明依据历史提出假设、保留失败、避免重复配置、收小失败干预及换锚点，但没有唯一确定以下选择：评价预算用于更多配置还是更充分评价；是否允许预测会暂时退化的辨因实验；换锚点时优先成绩还是互补机制；长历史如何形成有限工作上下文。这些选择会改变搜索行为，不能把论文作者的设计直接当作用户偏好。

另有两类问题不能仅靠 skills 解决：数值评价与目标优先级的差异，以及缺少容差、证据跨度和诊断数据。把指引写得更明确不等于执行器已实现相应能力。

## 逐项缺口

| 情景 | 当前指引已经具备 | 仍未确定的分支及可能误导 | 本次处理 |
| --- | --- | --- | --- |
| 小规模样本好看，完整评价尚未完成 | 区分样本集合与证据兼容性 | 是继续筛选，还是立即投入验证？若混淆，会把小样本偶然收益当最佳配置 | 询问 `evaluation_allocation`；统一比较口径始终是硬约束 |
| 合法对照预计暂时较差，但能区分原因 | 区分改善目标与信息价值 | 条件保护究竟约束每个实验还是最终接受结果？不能从“信息价值”推导出允许退化 | 询问 `diagnostic_regression`；已有保护界限和预算不能放宽 |
| 局部可用对照耗尽后换锚点 | 已确认应该换到兼容的已测锚点 | 次优成绩、不同机制、互补分支或不确定性，可能指向完全不同锚点 | 询问 `anchor_selection`；不能扩大动作范围 |
| 历史很长，需要精简输入 | 要求学习历史并保留反例，输出简短 | 若只保留最好/最近结果，会遗失失败边界；若反复拼接全部叙述，会加重上下文负担 | 询问 `working_context`；完整账本与选取上下文分开 |
| 联合改变两个区间后改善，单独改变时没有改善 | 已注明联合干预不能证明单区间因果 | 尚无完整交互效应设计。不能由一次联合收益断言各区间独立有效 | 保留“联合效应、机制未分离”；后续若设计因子对照，需外部预算和合法动作支持 |
| 平均误差降低，但少量结构异常或几何指标相互冲突 | 已确认先诊断极端事件，条件几何优先 | 缺少条件保护容差、邻域可接受退化界限、显著改善定义；不能认证稳定或完成阶段切换 | 参数保持未指定；原始异常保留，不用论文默认值代替 |
| Agent 的条件几何优先判断与执行器最佳配置不同 | 已要求区分偏好与记录中的最优结果 | 提示词无法改变实际损失、排名或结构诊断覆盖，不能声称数值策略已统一 | 明确报告代码差异；本次不改变科学协议 |

以上为新写的任务适配，不是复制论文提示词。没有运行这些论文的算法，也没有进行新采样或模型 API 调用。

## 实际代码边界

- `geometry_council.py::history_view/advise`：提供每个兼容已完成配置的指标、原始提案与区间诊断；当前输入声称覆盖全部兼容历史。选择性检索/摘要尚不是它的能力，未来采用时必须同时改变覆盖声明和证据来源记录。
- `geometry_calibration.py`：已有粗筛、细化、完整确认和嵌套槽位复用。当前阶段与晋级逻辑是外部代码；不是 Agent 可任意修改的预算。
- `geometry_runtime.py::validate_config`：正式组仍要求 50 次；`skill_assets` 只加载 analysis/proposal/synthesis 三个文件。关键决策规则必须进入实际加载的简短指引，不能仅放到它无法访问的 references。
- `geometry_protocol.py::choose`：按全部约束原子对的分子内部距离均方根偏差排序，再按引导强度及身份破同分。它没有实现“条件原子间距离优先”的新排序。
- `geometry_condition.py::loss`：使用冻结原子对与参考距离。邻域对单一参考构象的偏离并不自动等于设计损伤；指引不能假装已有设计有效性判定器。

问题一、四的策略可能需要执行器与输入构造配套。问题二的保护界限需要明确外部定义。问题三可以指导现有合法锚点选择，但不代表已实现多分支预算分配。所有回答只在适用条件满足时指导下一次动作，不恢复暂停任务或覆盖冻结运行。

## 访谈与后续写入

问题、实际答案与解释见同目录 `interview.json`。推荐选项不等于已确认答案；实际答案到达后才写入对应运行规则。保留直接回答、解释与实施状态三者的区别。

标准化方式沿用现有 skill 结构：YAML 的 name/description/metadata、简短正文、按需 references，以及生成运行指引的脚本。新策略使用现有 analysis、anchor_reason、evidence、prediction、falsifier、choice_evidence 字段，不追加输出模块，不固定迭代次数，不引入亲和力优化目标。详细论文讨论和访谈不进入每次推理输入。
