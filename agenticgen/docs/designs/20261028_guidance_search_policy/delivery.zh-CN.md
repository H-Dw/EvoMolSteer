# Skills 1.3.0：已确认的搜索偏好与待答分支

2026-10-28，Asia/Shanghai。本版只纳入第二次访谈中已经收到的第一项回答，其余三项保持待答。论文与代码核查详见 `assessment.zh-CN.md`；原始问题、答案与来源见 `interview.json`。

## 实际变更

用户选择“优先扩大筛选：先比较更多不同配置，再集中验证少数候选”。这与本轮问答的推荐选项不同；实现以实际回答为准，没有把推荐自动当成确认，也没有添加用户未给出的理由。

新增 `measured-search-policy-v1`，与此前的 `condition-preservation-design-v1` 并用：在外部协议支持分阶段评价时，优先覆盖更多不同且有辨别价值的合法配置，再集中验证所选候选。筛选数据用于安排确认，不能拿不同样本集合的成绩直接替换充分评价的最佳配置。预算比例、晋级阈值、候选数量均未指定。

标准 skill 主文件和维护参考已更新；传统三模块运行指引通过原有 renderer 生成。内部距离协议的 analysis 及主 GPT optimizer 指引也包含对应规则，proposal/synthesis 保留原有字段、计数与动作约束。所有模块标为 1.3.0，详细访谈和论文表不加入每次推理。

正式工作流仍按代码固定每组 50 次，本版没有加入自适应阶段调度器。固定组任务下，偏好体现为现有额度内的互补合法提案，而不是减少每组样本或新增试验。标定阶段、10/50质量抽查、科学代码、冻结运行与自动化均未改动。

## 手工情景复核

以下为指引的逻辑演练，不是 LLM 行为测试或真实分子测量。

| 输入情景 | 本版应给出的方向 | 不成立的推断 |
| --- | --- | --- |
| 多个未测配置可在已批准阶段中筛选，一个已有小规模候选成绩突出 | 先覆盖更多有不同假设价值的配置，再由外部阶段规则决定集中确认 | 一个小样本好成绩已证明超过完整评价的最佳配置 |
| 当前调用明确规定固定人口和提案数 | 保持调用协议，选择信息互补的不同配置 | 为贯彻“扩大筛选”自行减少样本、增加提案或额外调用 |
| 两个不同锚点导出同一有效配置 | 识别复用，不增加独立证据数 | 名字或谱系不同就构成搜索广度 |
| 新区域存在尚未解释的极端位移 | 仍先诊断已确认的风险问题；搜索广度偏好不能推翻条件保护 | 追求多样性就可以忽略异常或超出经验范围 |
| 暂时退化的辨因方案、两个候选新锚点或长历史压缩需要取舍 | 保持问题二至四待答，沿用既有约束并陈述未决点 | 第一项回答已同时批准探索性退化、某种锚点策略或选择性删减历史 |
