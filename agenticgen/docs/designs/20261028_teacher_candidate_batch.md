# 按教师编排候选与复用标定

## 执行与记账

同一教师、同一条件及同一采样协议的候选先写入 `candidates_batch.json`。每个候选保存实验来源、逻辑种子、原生槽位、四窗口归一化配置、该教师的标定倍率和实际强度。不同教师不混批，分别保存显存容量记录。

待执行候选少于 100 时首先放进同一次原生积分调用；候选不少于 100 时每批最多 100。只有明确的 CUDA/HIP OOM 才向下使用 80、60、40、20、10 的容量阶梯，选择严格小于本次容量的下一档，例如 90→80、50→40。10 是当前不可拆分的保存单位：五个种子各两个固定槽位。耗尽阶梯后明确停止。

OOM 保留失败调用目录，恢复外部随机状态，从同一初态重新执行尚未保存的候选；不改强度、条件、输出策略或种子，不增加候选数和科学尝试记账。若已经保存部分产品后在后处理发生 OOM，则停止并要求审计后处理，不回头重采。

预实验每个筛选阶段汇集不同常数强度。正式 Agent 先完成三个方向的提案及校验，再汇集三个方向的 150 个候选，通常分为 100 和 50 两批。后续阶段升级人口时只生成缺少的槽位。重复配置仍复用原产品，不计独立验证。

各候选独立使用其原生二十行随机流中的指定槽位，网络输出及完整坐标 VJP 使用各自的配置，梯度按逐分子损失求和，不对 batch 求均值。原生积分、最终输出规则、条件映射保持一致。非有限单元保存原始异常张量、计入失败，并使用不产出结果的占位单元使其他单元完成；它不会得到 COMPLETE，也不会减弱重试。极大的有限位移保留原测量。

**候选批容量与网络计算形状分别记录。** 真实验收发现，直接把物理网络 batch 从 10 扩至 20，在第 0 步就出现前向数值分歧，最终坐标及离散化学状态不同，虽然初态、映射与随机流相同。因此正式实现采用固定 10 样本的网络单元，通过独立 GPU stream 并发完成同一候选批的前向和 VJP。100 候选即最多十个并发单元，90 即九个；OOM 阶梯减小并发占用。不会把这种方式描述为单个 100 行 GEMM，也不宣称通过容差放宽消除了差异。原失败验收保留，不用于结果排名。

## 复用与选择初始窗口

两个接口均通过 `agenticgen/scripts/run_uniguide_geometry.py --config 新配置.json` 调用：

1. `reuse-calibration --sources 教师来源.json --initial-scales 窗口刻度.json`：导入已有完整标定及其成功、失败和槽位证据。必须已完成目标目录的 prepare 和工程 acceptance。每个教师可指向不同来源目录。
2. `select-initial --initial-scales 窗口刻度.json`：当前目录已有完整标定时，直接指定初始化配置。

教师来源文件格式：

```json
{"6pyy_H7S_A_402":"/workspace/已完成标定甲", "3w54_RNB_A_504":"/workspace/已完成标定乙"}
```

窗口刻度文件格式（下列仅说明格式，不是已验收的强度建议）：

```json
{"6pyy_H7S_A_402":[0,1,0,-1], "3w54_RNB_A_504":[1,0,-1,0]}
```

四个值是归一化整数，顺序对应 10–25、26–50、51–75、76–90 步。必须落在各自实测区间与 [-10,10] 的交集。零表示实际强度为该教师的 λ。接口不接受旧坐标损失的强度冒充新刻度，也不自动选择未标定的 λ。

随后 `run-version GD01` 先测量指定配置的 50 个候选（命中完整测量则直接引用），将该结果纳入历史，再开始 Agent 提案。指定配置、实际强度和来源冻结于 INITIAL_GUIDANCE.json；首版开始后不得改写。初始化增加的候选按正式预算计数，循环轮次数仍由配置控制。

复用要求条件、映射、模型、原生实现、输出策略、数值环境、随机初态及采样源码绑定完全一致。导入复制而不修改源产物，保留源尝试账本哈希，在新目录不重新记成新增采样。仅粗筛、缺少完整人口确认、失败的标定、不同协议或旧实现均拒绝。当前 2026-10-28 两教师各 130 次粗筛均因最优点在边界停止，尚无可导入的完整 λ；本次不会伪造或扩大该预实验。

## 验收边界

本地只做静态检查；固定提交推送 GitHub 后在独立远端目录运行单元回归与两教师真实模型工程验收。真实验收比较完整 100 步的不同强度、不同随机槽位的混批与单组执行，同时核对终态、轨迹、离散状态和 RNG。另尝试 90 候选短程显存探测，并保存实际 OOM 回退证据。工程样本不用于标定或科学排序。不恢复 UG05，不改历史实现和账本，不自动启动新标定或正式版本。
