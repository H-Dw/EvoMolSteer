# 逐步重匹配与跳跃探索：2.7.0

本次实现对应用户的两项修订：允许每步与终态重新匹配原子；将 Guidance Agent 的任务收敛为探索可能更优的配置，三种假设仅区分探索幅度。新绝对坐标实验默认采用 skills `2.7.0`。原 `2.6.0` 及更早发布文件保留，显式选择旧发布时仍使用其原有冻结匹配与动作契约。

本次只交付代码、skills 和工程验证，没有启动远端实验、标定或真实 LLM 调用。

## 匹配、损失与化学注入

新条件字段为：

```json
{"atom_assignment_policy": "per_step_and_terminal_endpoint_hungarian"}
```

设条件原子有 K 个，参考坐标为 y_j；当前第 t 步模型的未覆盖终态预测坐标为 x_{t,i}。蛋白单独确定固定正 Kabsch 测量变换 T，配体不参与拟合。每步选择有效生成槽位到条件原子的单射：

\[
\pi_t=\arg\min_{\pi\ \text{为有效单射}}
\sum_{j=1}^{K}\lVert T(x_{t,\pi(j)})-y_j\rVert_2^2,
\qquad
L_t=\frac{1}{2K}\sum_{j=1}^{K}\lVert T(x_{t,\pi_t(j)})-y_j\rVert_2^2.
\]

Hungarian 在脱离计算图的 CPU 双精度坐标上求对应；当前选中坐标仍通过原完整预测计算图向采样状态反传。匹配切换处目标是分段光滑的最小值，不对离散索引求导。没有增加 affinity 梯度或随机数抽取。

采样沿用 raw999、100 区间、10–99 步引导。前缀中的只读损失也按当前预测匹配；从第 10 步起记录初始及最新对应。每步原生更新与坐标 guidance 后，化学 inpainting 使用**该步坐标损失同一份对应**，注入原子化学通道和条件内部键。对应变化不会重置此前已演化的其他槽位化学状态。没有坐标、self-conditioning 或最终输出覆盖，也没有恢复 3 Å 限幅。

终态对实际返回的最后循环未覆盖预测重新运行 Hungarian，再计算条件区域坐标均方根偏差和最大条件原子坐标误差。它不额外执行模型前向、不修改坐标，也不将化学模板覆盖到最终输出。raw999 的第 99 步更新仍不进入返回端点。

主指标表示最优对应下的几何覆盖，不能据此宣称同一批生成原子或化学身份得以保持。因此另报初始对应和最后引导对应在终态上的条件区域坐标均方根偏差，以及终态相对最后引导的换位比例；前两项以完整人口原始均值汇总，不参与排名。原始记录和逐步对应均保留。

恢复时先校验 checkpoint 中最新对应与 `previous_assignment` 一致，再对下一步当前预测重新匹配。首次对应缓存仅为初始来源审计，不约束之后的匹配，也不能通过恢复重新定义已完成轨迹。当前绑定张量按物理行组替换，不逐步累积缓存。

## 三种探索强度

实际强度继续使用线性格点：教师冻结基准加格距乘整数刻度，默认格距 10。Agent 提交锚点、窗口和整数增减档位，由执行器生成实际数组。

探索幅度定义为所有更新窗口的整数档位变化绝对值之和。默认配置如下，三档端点可以在外部配置中调整，但必须为递增整数并覆盖合法动作总上限：

| 假设 | 总绝对档位变化 | 总绝对实际强度变化 | 可用方向 |
|---|---:|---:|---|
| focused | 1–2 | 10–20 | 增加、降低、混合 |
| expanded | 3–6 | 30–60 | 增加、降低、混合 |
| bold | 7–12 | 70–120 | 增加、降低、混合 |

单窗口最多变化 4 档，默认总上限由 6 提高为 12 档。标记为 `bold` 并不能代替真实改动：执行器按数组改动核验 `exploration_tier`，错误标签拒绝。表中总变化是各窗口绝对变化的和，不是每个窗口都允许变化 120，也不代表总强度守恒。

工作邻域只是优先级提示。使用已确认强度的较大联合跳跃可以直接按正式人口测量；引入未确认的实际强度仍通过受预算控制的 20→50 范围取证。已确认常数档不证明所有窗口组合安全。声明域、失败记录、精确配置去重、预算和单侧高偏差组级统计保持约束作用，不自动扩界或补样。

## Agent 输出与任务角色

保留提案与综合选择两个实际 LLM 角色。每个角色读取三种探索强度，而非分别建立增加、降低、再分配的执行配额。

skills 要求：

- 使用兼容已完成历史寻找潜在更好的落点，可采用其他较好锚点并联合改变窗口；不要求逐窗口证明作用。
- 机会相近时倾向更宽或更激进的探索，避免因小步更容易解释而长期停在极窄邻域；不为激进本身选择已预期明显更差的配置。
- 不设计机制验证、单因素消融、参数反证或已知劣势方向的响应曲线。不要求定量预测、生成动力学解释或 falsifier 字段。
- 只提交精确锚点、探索强度、窗口整数改动、原测量/已读回执身份、简短改善机会与不确定性。未知可以直接说明未知，不能伪造证据。
- 三档不要求各提出或执行固定数量；允许只执行有希望的方案、保持现任或请求范围证据。轮数继续由外部参数控制。

执行器保留严格 JSON、动态实际强度核验和原实验身份识别。提示中的工具说明也改为读取已有结果来支持未来搜索，取消面向机制反证的旧描述。

## 配置与迁移

完整实验配置可合入 [新控制配置片段](../../../configs/uniguide_linear_control.json)。该片段仍不包含模型、条件文件和冻结初态源，不是可以直接启动实验的完整配置。

新匹配政策写入条件、化学绑定、配置及标定域。条件哈希和采样实现绑定均变化，**不能复用冻结对应旧协议的 λ、排名或验收回执**。需要新结果根、固定提交真实模型验收，以及两教师各自的新标定。旧目录、manifest、发布、失败账本和测量不覆盖。

仅修改 skills 文案不构成科学采样变化，但本次同时修改对应策略，因此必须按新科学条件处理。旧 2.6.0 说明与证据是历史记录；最新验证见同目录 `dynamic_validation.json` 和 `dynamic_regression.xml`。
