# 静态验证收敛与动态保护保留

按用户最新要求，保留动态数值有限性、配置中的 3 Å 引导增量限制、恢复对应一致性和重复实验识别；精简静态条件、冻结对应和文件绑定的重复验证。本次只修改代码并做工程测试，不恢复已归档失败的实验，不重采已保存的 80 个候选，不创建或恢复实验巡检。

`CoordinateObjective` 在控制器加载时验证并复制条件，准备参考坐标、蛋白旋转和平移；常数张量按设备与精度复用。`AssignmentState` 在首次匹配或恢复后的首次使用验证索引范围和一对一对应，随后复用对应张量。外部单次 `loss`、`metrics` 接口仍完整验证输入；恢复时仍校验 checkpoint 对应哈希，缺少冻结对应时拒绝重新匹配。

每次损失计算仍检查当前张量形状、设备和所选原子是否被当前掩码屏蔽。网络输出、预测坐标、损失、输入梯度、引导增量及更新后坐标的动态有限性保护保持原实现；健康张量继续直接返回原对象，不增加保护性计算图节点。候选局部限制器、3 Å 配置、原生随机流、raw999 输出、10–99 步窗口和化学通道注入代码不变。

合批调度入口计算一次当前文件兼容性绑定，分片保存与人口汇总复用该绑定，不再各自重读源码和五份初态文件。复用只限同一次任务调用，教师和条件身份仍核对；下一次入口重新计算文件哈希，不使用跨任务全局缓存。已完成结果仍核验回执内容和产物哈希；失败 claim 不删除，重复配置仍引用原测量而不追加预算。

修复 `geometry_sampling.py` 缺失的 `h5py` 导入；新增固定对应记录也进入 COMPLETE 文件哈希。CI 增加三个坐标执行模块的 Ruff F821 未定义名称检查。测试覆盖准备后损失的精确完整坐标反传、无额外随机数、一次静态准备、多步动态失败检查、恢复与映射篡改、每次合批入口的绑定次数，以及真实 HDF5/SDF 后处理和回执复用。模型构建器由测试夹具提供，不把这些工程测试计为科学候选或新的标定证据。

本地 Python 环境没有 PyTorch、RDKit 和 h5py，仅执行语法与静态检查。数值、HDF5 和结构测试使用远端既有 DTK 环境，在独立固定提交目录执行；结果另存机器可读验收记录。新的源码绑定不冒充旧失败实验的冻结实现，已有条件、配置、预算、失败标记和历史运行目录保持原状。
