# 反传数值一致性：冻结第10步的因果定位

诊断完成时间：2026-10-29 14:06:45，Asia/Shanghai。正式运行仍停止在工程验收，未开始新λ标定、GD01采样或LLM调用。

## 结论

已定位到合批控制器的数值保护路径与独立控制器不一致。`CandidateControl.check_rows()` 在所有数值正常时也返回 `torch.where(...)`，而独立控制器完成有限性检查后直接返回原张量。`geometry_condition.measurements()` 对内部距离分支的端点使用前者，互作距离分支继续使用原端点，改变了梯度支路的汇合方式。

在原失败的两个6pyy固定状态上，仅加入 `check("distance endpoint", endpoint)` 这一处身份等价保护，即可**逐位重现保存的合批输入梯度**；去除这一处额外图节点后逐位重现独立组梯度。前向预测及损失均不变。这个结果把差异定位到了具体代码路径，不再只是关于并发或重复索引的推测。

这里的“恢复一致”仅指冻结第10步的诊断。生产实现尚未修改，也没有重新执行100区间验收；不能宣布正式合批问题已经修复。

数学上，全部健康时 `where(false, 0, value)` 与 `value` 相同；浮点反传却不保证不同图结构的加法结合顺序相同。实验确认了额外节点与差异之间的因果关系；对引擎内部每一次加法的调度顺序未作指令级追踪，关于舍入/梯度汇合次序的解释应与这一验证边界区分。PyTorch也明确说明数学等价计算不保证逐位相等，浮点加法不满足结合律：[PyTorch 2.9 数值精度说明](https://docs.pytorch.org/docs/2.9/notes/numerical_accuracy.html)。

## 是否因为距离过多或出现“多份梯度”

目前证据不支持这种归因。6pyy的44个互作距离对对应9个配体槽位，数学重复配对数为0。同一原子连接多个约束时，其梯度本来就应是所有相关距离项梯度之和；这是链式法则，不是重复反传故障。

各距离分量使用平方误差的**均值**，再按分量权重合并，不是把44个误差未经归一化直接相加。当前步长度归一化分母使用 `detach()`；其中较多的分子内距离运算增加计算量，但不会经该分母产生额外梯度路径。每次前向创建新的坐标叶张量并调用 `autograd.grad`，没有依赖持续累积的参数 `.grad`，也没有发现跨候选梯度混合。

多距离支路确实提供了梯度汇合的位置，但本次触发因素是**独立与合批路径在这一位置的图结构不同**，不能简化为“距离数量太多”或“有多份异常梯度”。同一图反复执行稳定，不是已经证实的随机竞态。

另一项应单独讨论的建模问题是按“距离对”平均仍会使约束较多的原子占更大权重。本条件槽位0关联8对，槽位13、14各1对。不同约束也可能方向冲突。这影响优化目标的分配，**不是本次一致性失败的证据**；改为按原子平均会改变科学目标及λ，不能作为等价工程修复偷偷引入。

## 为什么从第10步开始、最后会停机

10–99步策略在第10步首次启用坐标梯度。此前没有这条VJP，因而两路径相同；第10步预测与损失相同但输入梯度开始不同；第11步以后轨迹出现分歧。原已完成验收轨迹的最终未覆盖预测最大单原子差分别为0.0046889523 Å和1.2817190625 Å，后续也出现离散化学通道差异。

验收在比较完整轨迹后失败，并不是程序执行到第10步就崩溃。最初很小的差异不能以最终结果仍可比较为由忽略。原轨迹应用引导增量最大仅约0.0001554253 Å，3 Å限制器没有触发；增量上限控制局部大步，不保证不同浮点图的轨迹一致。
