## 具体 prompt 与参数选择问题

第一，范围额度信息与“合法动作”混在一起。baseline6pyy 第1轮消耗两个范围配置槽，之后两轮仍从 90 向上提出新范围动作。`linear_scale`/工具返回的 `legal_unmeasured` 证明参数结构与边界合法，不代表 `linear_runtime` 一定有预算准入；最终六项返回 `budget_limited`，没有新测量。实际 packet 已包含额度，故不是缺字段接口错误，而是 Agent 未充分执行约束、工具分层也容易让它误读。下一版可将剩余额度为零的动作在提案前显式排除，并把“可执行”与“格式合法”分开；本次没有据此重放或提额。

第二，探索强度标签相对旧锚点计算，未保证相对当前最优的跳跃幅度。prefix3w54 第4轮 [110,110,90,110] 被说明为 expanded、4 ticks，实际只离当前最佳 [100,110,90,110] 一格；第5轮 [80,110,90,110] 被说明为 bold、7 ticks，实际只离最佳两格。两者对其声明旧锚点的校验可通过，但空间覆盖仍集中在最佳附近。后续应同时展示到声明锚点和到当前最优的 L1/最大单窗距离，按最终落点去重与控制覆盖；不把合法标签误当探索多样性证据。

第三，说明仍偏向拆分机制与补齐响应曲线，偏离“追求潜在更优路径”。five6pyy 第3轮 synthesis 把已测单窗改动外推为“约 0.0005–0.0008 Å/单位”，没有未测组合的实测支持；第4轮明说某分支“先验上更可能变差，其价值在于同时读取……叠加”；第5轮为 `complete the w4 profile` 选择 60/70。prefix3w54 也反复以 `clean single-window reads`、消除混淆作为选点理由。数据支持哪些配置已经好/差，不支持推断生成机制或线性可加。后续 skills 的执行评价应询问“该完整落点为何还有合理的更优机会、跳到哪片尚未覆盖区域”，并禁止仅为解释/证伪/补曲线消耗动作。这里是实际策略质量问题，不是可绕过冻结失败规则的工程异常。

第四，最优起点与范围额度仍会导致单边收缩。6pyy 仅有 40/50/60/70/90 确认档，90 已是可用上端且两个范围配置额度耗尽，后续大幅跳跃主要意味着降低前段。Agent 很快集中在 w3/w4 的细小邻域。格距10解决了指数过快，但没有自动提供起点两侧的可用幅度。下一轮设计应预留靠近当前最佳的两侧范围证据、以可测余量选择起点，同时将范围扩展与正式动作预算准入直接展示；不能由本次未测的100/110推断安全或改进。

第五，实际终局说明存在可核验的阅读错误。five6pyy 的 `analysis_final/synthesis` 把工具的“43 改善 / 7 变差”写成“多数变差”。本地按原50槽位复算确认是43改善、7变差，而少数较大退步使平均值变差 +0.001282857 Å。保留最小均值 checkpoint 的决策正确，人数叙述错误。它还将尚未测量的其他窗口组合概括为“已无未覆盖”，实际只能说已测晚段邻域较平、范围额度耗尽。应由程序显示原始计数与明确有限域，避免让自然语言扩大结论。本次保存该文本，没有回写美化真实回执。
