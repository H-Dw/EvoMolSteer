# 确认域上界问题的定位与2.9.0实现复盘

记录时间：2026-11-01，Asia/Shanghai。此项是控制接口和skills工程修改；未启动新分子采样、标定或真实LLM，未部署任何旧固定执行目录，也未更改自动化。

## 具体原因与上下游门控

“最佳点在确认域上界”不是已经证明scale越大越好的科学结论。旧策略把有限的测量覆盖集合当成后续动作准入集合，又把取证额度绑定到很少的配置身份。6pyy首轮后最佳uniform90恰好是最高确认档；100以上是未测，不是已知较差，也不是物理上限。

| 环节 | 旧行为与实际证据 | 对探索的限制 |
| --- | --- | --- |
| 预标定粗筛和晋级 | linear_calibration.promotion_levels依据10/20人口选最多4档，然后固定晋级名单；6pyy完整确认40/50/60/70，最佳70。 | 完整50人口赢家变化后，不围绕该赢家重新分配完整确认；小人口选优不保证完整赢家位于覆盖内部。 |
| 参考域与动作路由 | linear_scale.resolve_action将任何新标量档路由到range_evidence；确认档兼作正式动作白名单。 | 声明硬域10–200和偏好区间并不等于当前可执行域，正式额度无法直接用于未确认档。 |
| 前沿额度 | 6pyy首轮80止于20，90晋级50，两项都占配置名额；随后remaining_configurations=0，尚有50次范围尝试。 | 失败/未晋级不退款符合旧政策，但两个配置的硬限额让剩余尝试无法使用。 |
| 工具和角色校验 | audit_action_batch能返回legal_unmeasured；proposal/synthesis主要核对参数、ID与结构，未将实际准入做成共用硬门控。 | 参数合法的方案能被选择，即使LLM已读到配置名额为0。 |
| 真正执行 | linear_runtime.range_evidence到执行阶段才返回budget_limited。第2/3轮六项全部新增0。 | 浪费两轮决策机会；不能把它们统计成“采样后表现差”。GPU和原始采样并没有在这两轮失败。 |
| 后续选择 | 第4轮只测确认档内下调，第5轮hold；结束仍余550次正式尝试。 | 局部覆盖被误作搜索空间受限，窗口解释又进一步压缩了候选机会。 |

以上来自已读取的原始prompt、REQUEST/工具回执和完成组，见[旧基线逐轮复盘](../20261101_all_results_summary/RMSD对齐与基线迭代复盘.md)及同目录机器读数。预算保护本身按旧协议正常执行；缺陷在晋级覆盖、额度设计、路由耦合和准入检查过晚的组合。不能通过删除claim、补样、退款或篡改旧确认域解决。

## 更宽的探索域如何实现

新策略为linear-open-domain-v2。把三个对象拆开：外部声明的合法格点、已测确认的证据、当下可支付的动作。默认格点10–200、单位10；域内未测完整配置直接按正式50人口测量，不再占另一个仅两配置的前沿名额。声明域之外依然拒绝，不自动扩边界；未知格点不带稳定性或收益保证。

预标定在原350次上限内从20/50/80/110/140/170/200宽域粗筛，最多10个粗筛档和6个完整确认档。每次完整赢家改变，围绕实际完整赢家优先确认±10/±20支持；保存缺失邻居、耗尽原因和实际覆盖。有限预算不能保证找到内部最优，若赢家确实在声明硬边界或覆盖边缘，应如实报告，不能强选一个更差的中心。

动作仍为每窗最多4个tick、总计最多12、每轮最多3项，三种幅度沿用线性整数跳跃。新linear_admission同时服务只读工具、两角色输出校验和执行前核对：先校验每个备选能独立支付，再校验选中组合累计成本；计入既有10/20人口复用的真实增量、教师额度及全局额度。损坏的测量回执会中止审计，不能伪装普通参数错误或预算不足。新schema只提供propose/hold，移除本策略已不使用的request_domain_evidence选项。

## skills怎样约束优化思路

2.9.0新增独立不可变发布包，原2.8.2十个文件的SHA和Git内容均保持。两角色实际收到五段方法：

1. 先读初始标定performance、当前全局最佳、实际合法格点与可用预算，第一轮也不能略过标定。
2. 回顾当前最佳的真实前置节点、参数变化、已存选择摘要与测量结果；把过去理由当待审搜索猜想。
3. 选择有机会超过全局最佳的不同完整落点；不以解释窗口、补响应曲线、消融、排除混淆或反证为实验目标。
4. 先审计备选，再审计选中组合；只因“结构合法”不能选中预算已耗尽动作。
5. 严格原生工具提交，保留显式控制数组、3000字符、证据身份、动作及原唯一格式修正等校验。

控制对象新增必填optimization_target，显式绑定真实calibration_source_id、incumbent_source_id、reviewed_path_sha256及固定purpose=seek_potential_global_improvement。回滚只能从已复盘的当前最佳起步，path_relation必须为redirect_from_reviewed_best。新优化工具只暴露人口汇总、配对结果比较和动作审计；步级窗口/增量诊断仍留在工程数据中，退出当前优化工具与主要历史prompt。

这使优化目的、准入和路径绑定可验证；自然语言理由仍不能靠一个purpose枚举保证完全服从，不能据离线检查宣称线上LLM合规率100%。独立合成前向检查未设计机制实验，也未虚构工具回执；真实provider行为仍需新根实测。

## 标定根与回滚路径

旧运行时choose(history)已经包含标定；先前“最佳Agent轮”表是用户要求的另一个展示口径。新实现将区别写入接口与持久结果：CALIBRATION_BASELINE是初始默认节点，GLOBAL_BEST只有严格更好的完整50人口测量才更新；ROUND_COMPLETE另保留本轮新测量最佳。持平不换根，全部Agent轮变差时最终代表仍是标定。探索本身可能失败，不能承诺每个新配置都更好。

已完成旧实验按这个默认展示口径重列在[默认全局最优节点对比](默认全局最优节点对比.md)。3w54四窗口基线仍应选初始标定0.279239 Å，而不是第5轮0.279807 Å；6pyy首轮90的0.590092确实超过标定70的0.637972，因此可以替换初始根。

回滚保留原相邻两次下降触发，并补“两次相邻有新完整测量轮均未改进全局最优”。即使两轮成绩相互改善，但一直差于标定，也应重新出发。空测量/hold不制造下降。prompt携带最佳节点的实际anchor父链、当时已存选择摘要、改动和结果，以及最近失败旁支；父节点缺失、循环、来源不兼容或决策记录不一致会拒绝。标定节点没有Agent父亲时明确它来自程序标定，不能编造前置推理。

用户所需的回顾落实为可核验的已存决策路径和简短复盘，不索取或补写模型隐藏思维链。路径SHA绑定真实上下文，回滚动作必须改变方向而不是重采最佳。
