# 开放线性探索域、标定根节点与决策路径回顾

本任务只修改控制接口和skills、运行离线CPU回归并提交推送；不部署固定运行目录，不启动新科学实验、标定、LLM或自动化。现有实验、失败、账本和2.8.2及以前的skills发布包保持原样。

## 已确认的问题

6pyy标定按10/20候选的赢家预选最多4档晋级50。50候选的赢家可能换到晋级集合边缘，程序没有围绕这个新赢家重新分配完整确认。第1轮探测80/90又耗尽两个范围配置名额，即使尚余范围尝试和700次正式额度，所有包含未确认档的动作仍走范围通道并被拒绝。动作审计的legal_unmeasured仅代表结构合法，未代表当前预算可执行。第2/3轮因此没有采样。

运行时原本已经把标定纳入全局最优。此前“最优迭代轮”的单独报表排除了标定，这与默认全局最优不是同一个视图。新版须明确标定根、全局最优和本轮新测量最优三个对象。

## 新版2.9.0的约定

1. 新默认为`linear-open-domain-v2`，旧线性协议继续显式可用。硬边界默认10–200，格距10；未知区域是待测而不是稳定保证。确认档是证据，不再是正式动作的白名单。域内未测完整配置可直接进入50候选正式测量，保留精确失败/重复拒绝、真实预算及严格源码兼容检查。
2. 新预标定在同一350次上限内作宽域粗筛与动态完整确认：起始20/50/80/110/140/170/200，最多10个粗筛档、6个完整确认档；完整50赢家改变后，优先补它两侧的10/20单位支持。没有足够预算或遇到已测边界时如实标记覆盖不足，不故意选择较差中心，也不承诺有限预算必然取得内部最优。新协议不预留另一个会阻塞正式搜索的范围配置名额。
3. 保留每窗最多4个整数tick、总计最多12个tick、最多3个实际动作及既有三种探索幅度；扩大的是可准入的域，不采用指数scale，也不自动扩硬边界、加预算或补样。
4. 动作审计报告当前可执行性、额外尝试成本、独立候选与整组选中动作的预算。proposal核对各备选的可执行性；synthesis与真正执行前核对选中组合累计成本。预算不足的动作不得以合法未测的身份混入可执行方案。
5. 初始标定最佳为默认根节点。全局最优只被严格更好的完整50候选测量更新；差于或等于标定的Agent结果不能替换它。第一轮实际prompt必须含标定ID、performance、配置和比较目标。保留独立的本轮成绩，不能用单调累计最优判断是否退步。
6. 回滚除连续下降外，也识别两次相邻有测量轮均未改进全局最优。提供最优节点与真实前置锚点的有界决策路径、当时选择摘要、参数改动和结果，以及最近失败旁支。回顾对象是已保存的可核验决策摘要，不索取模型隐藏思维链；不得补写不存在的父子关系或重新生成最佳节点。
7. 新skills分段执行：读取根节点/当前最优与可执行域→回顾最优路径与失败旁支→提出可能更好的完整落点→预算/重复审计→严格工具提交。机器契约限定目的为优化全局最优，并将方案绑定实际标定根、当前最优及决策路径SHA。禁止以解释窗口、消融、反证、补曲线或证明机制为实验目的；保留结果未知和失败的可能，不能保证每次探索均优于标定。

## 验证

- 用发生过的“最高确认档90、范围配置0、仍有正式预算”复现，确认新域内100/110等配置可用，同时旧协议仍按原约束解释。
- 用小人口赢家与完整人口赢家不同的CPU测量夹具，验证确认会围绕完整赢家移动、上限350且无失败重采。
- 验证独立备选与选中组合的预算区别、提交前与执行前准入、错误目标/父链绑定的拒绝。
- 验证所有Agent配置变差或持平时根节点仍为最优，第一轮prompt包含标定performance；出现更好子节点后回滚包含真实父链和失败旁支。
- 验证2.9.0四模块实际加载、strict原生工具字段和3000字符约束，旧release逐文件哈希不变。真实GPU采样、VJP、随机流和UG04串行调度不作修改。
