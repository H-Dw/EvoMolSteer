# λ范围为何停留在0–1：历史决策与实现核对

日期：2026-10-25。范围为已完成V6–V30的范围决策文件、正式组统计及固定源码；没有新增实验、修改科学代码或运行测试。

**结论：0–1是实际被持续冻结的搜索域，不是gradient guidance算法的必然限制。从V11起，主agent已经有条件扩幅的授权，却一直没有实施。原因包含偏保守的范围决策、局部探索优先与证据收集未形成闭环；正常部署入口还存在没有接通扩幅的工程缺口。现有实验没有回答λ>1是否更有效，不能将缺少扩幅证据写成大尺度无效的证据。**

## 1. 授权与实际执行不同

[原计划](../../plan.zh-CN.md)“上限U、粗探索尺度s、精细分辨率q”规定：V6–V10初始U=1；完成V10复盘后最早V11允许根据边界响应、实际位移/裁剪与未解决假设扩幅。级别为1→5→10→15…，每版最多一级；精度仍为0.1，扩幅后每轮四案最多一个range probe。U升到5并不要求每个方案都用λ=5。

V10→V11至V29→V30共20个边界的实际记录为：18次hold、2次恢复历史范围（V13恢复V10、V25恢复V17），0次扩幅。各版有效政策始终U=1、coarse=0.2、q=0.1、max_range_probes=0。下层agent不能越过已冻结域，范围改变应由版本间的GPT主agent处理。

[全部1000组正式统计](../v6-v30-final/group_metrics.csv)（25版×两teacher×五轮×四组）显示：

| 窗口 | 实测λ范围 | λ=1的组数 | λ>1的组数 |
|---|---:|---:|---:|
| W1：10–25 | 0–1.0 | 6 | 0 |
| W2：26–50 | 0–0.9 | 0 | 0 |
| W3：51–75 | 0.1–0.9 | 0 | 0 |
| W4：76–90 | 0–1.0 | 4 | 0 |

仅10/1000组触及任一窗口上界；这些组也不是独立重复实验，部分数组跨版本重复。

## 2. 主agent当时为何一直hold

- [V10决策](../v10_strategy_review/range_decision.json)：早段高侧恶化，末段虽有条件收益，但缺少该上边界的实际位移、裁剪与扩幅容量证据，因此保持U1。
- [V16决策](../v16_strategy_review/range_decision.json)：明确认为“位移比残余误差小”本身不足以批准扩幅，优先保留域内释放与曲率问题。
- [V17决策](../v17_strategy_review/range_decision.json)：内侧已有收益、继续增强有反转、迁移依赖背景，因此继续域内搜索。
- V18以后多次继续沿用“缺少有利上边界交付/裁剪/容量证据”，两次回滚还要求同时恢复历史范围。

其中部分局部判断有实测依据，但不足以支持全程不检验更大尺度。**主agent把“尚未取得证据”长期作为hold理由，却没有明确安排如何在既有预算与授权边界内解决该不确定性，也没有及时报告所需证据与审阅范围之间的缺口。** 下层又因U1和零range-probe配额只能进行局部搜索，于是形成持续保守的循环。不能将其归因于用户从未授权扩幅。

## 3. 已有结果既支持谨慎，也留下了尺度问题

V17 Top1在相同背景下，早段0.7→0.8使Mean增加0.001663303，0.8→0.9反而下降0.027153921。V20 Top2早段0.9→1.0时，C从1.906037015增至1.917757345Å，Mean从4.157487688降至4.127387323。因此“所有窗口一起加大”并无现成支持。

但V10 Top2末段在同一背景 `[0.1,0.5,0.5,λ]` 呈现不同趋势：

| 末段λ | 平均条件RMSD Å | Mean pIC50 |
|---:|---:|---:|
| 0.5 | 1.919092062 | 4.210453224 |
| 0.7 | 1.918480864 | 4.210388060 |
| 0.9 | 1.917862156 | 4.210312099 |
| 1.0 | 1.917550419 | 4.210252409 |

末段加大仍持续改善条件，只付出很小的平均评分代价；到1.0没有显示条件收益饱和。这是值得区分窗口、继续判断尺度的已测方向，不能由早段恶化否定。但此表也不能外推证明λ=5有效，更不能证明能补偿另一个背景的条件损失。

## 4. λ数值不等于实际位移

实际实现见[reward.py](../../../src/agenticgen/adaptive_schedule/vendor/reward.py)：

```text
raw_delta_native = λ × dt × gradient_native / coord_scale²
clip_factor = min(1, 0.025 Å / max_atom_norm(raw_delta_world))
delta_native = raw_delta_native × clip_factor
```

梯度经当前一步模型预测终态回传至当前坐标；奖励对条件原子取均值，没有把最终梯度归一化为单位向量。实际力度受dt、梯度模长、模型Jacobian、坐标尺度和裁剪共同决定。0–1内可能已有明显作用，也可能某些窗口作用很弱；不能仅按λ的数值判断。

已有原生验收收据记录Top1/Top2最大单原子指导位移分别0.010812995/0.003432019Å，低于0.025Å上限。这是验收调度的真实值，**不是V17各窗口的上边界测量**。V17选定私有说明还引用某第三窗口最大位移0.000126Å及无裁剪；这只是已保存agent说明中的局部数值，本次没有重新读取轨迹核验，不代表全版。

因此“某些窗口力度可能不足”是合理的待检验假设。若未裁剪，固定状态下λ放大会线性放大当前步增量；完整轨迹还会改变后续梯度与模型状态，不能由此保证终态收益。若已裁剪，提高λ也可能主要被上限抵消。现有记录不能将全部失败归因于0.025Å上限或λ太小。

## 5. 正常部署入口存在未接通的扩幅路径

从V11引入的固定源cf46ab27到V17源a245eb0a、V30源d823ddf5，正常启动入口都存在以下结构：

1. `start_reviewed_version.py`拒绝已存在的目标版本目录。
2. 无回滚时调用`load_version_policy`；新版本没有政策文件就复制上一版，因此继续U1。
3. 启动入口没有读取已提交`range_decision.json`中的新政策，也没有向approval写入`range_expansion`证据。
4. 但`version_gate.py`在U升高时要求`boundary_response`、`delivered_movement_and_clipping`、`unresolved_hypothesis`及固定文档hash。

这意味着底层政策与门槛支持扩幅，而普通部署流程没有把主agent的扩幅决策接入。把JSON写成`expand`本身不会应用新范围，也不能通过预放目标目录绕过。扩幅需要先补上正常入口并做限定的远端验证。

**这不是历史中已经发生过的“扩幅被拒绝”故障：所有范围决策本来就是hold或回滚，没有一次提交了扩幅意图。** 因此直接原因仍是主agent决策；工程缺口是这次源码核对发现的额外问题，说明扩幅能力虽写进计划和底层规则，却未在实际主路径上闭环。

## 6. 对既有结论的修正

V17应描述为“U≤1、既定步长和预算下的历史最好”，不能称为已充分探索guidance scale后的最优。V6–V30主要比较了局部调度与skills适配，没有检验跨量级指导尺度。

后续若重新立项，尺度问题需要单独定义：按窗口区分条件收益、功能代价、实际指导/原生位移比与裁剪，并在修复后的版本边界实施有明确假设的有界扩幅。扩幅上限、实验配额和位移上限是不同变量，不宜一起更改。当前仅记录审查结果，没有自动启动V31、修改已完成版或恢复已撤回方向。
