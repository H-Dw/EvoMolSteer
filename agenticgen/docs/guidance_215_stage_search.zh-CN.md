# Guidance 2.15.0 阶段路径探索

本版本使用同一Guidance提案角色，在首轮提出并冻结Early/Middle/Late连续阶段。阶段映射独立于采样身份，各窗口保留独立scale。当前实验配置为 `configs/uniguide_stage_path_search.json`，仍叠加绝对坐标基础配置使用；完整标定仍限定已有六窗与两位教师背景。

首轮要求不同Early窗口的独立提案；每轮至少两种真实父节点相对的Early符号方向。采用新Late背景后，下一轮必须在该背景下进行Early修订。历史非赢家前缀一次后缀适配未改善便暂停，新相关后缀证据可重开。所有评价使用完整50候选condition对齐RMSD均值，中途读数不参与剪枝。

新增只读 `lookup_schedule` 返回已测数组的证据ID、成绩和零新增成本。重复数组仍需从proposals中修正移出，不静默删项。`audit_action_batch` 需要search_focus及stage_partition；首轮传阶段对象，后续传null。首轮最终提交包含stage_partition，后续最终提交省略该字段；DECISION与轮次回执由程序携带已冻结映射。

阶段状态从完整轮次回执重建，映射在采样前另存于每位教师的冻结记录。末轮更新后产生的待复查义务保留在最终路径上下文，不增加轮次。失败采样消耗预算，不补样。

阶段组件支持不同数量窗口的分组与审计；不代表本次已增加任意窗口数的标定流程。旧release与接口按版本分支处理。本次没有启动线上分子采样，行为测试不证明新的科学收益。

技能入口位于资源目录2.15.0的skills子目录，runtime副本通过 `scripts/build_guidance_215.py` 校验；发布前使用 `--sync` 同步，发布后须以新版本变更。

2.15.0以阶段方向、首轮独立试探、焦点与旁支额度统一审计，替代旧版多窗口bold必选及三种改动集合要求，避免有限预算下与独立早期试探发生冲突；距离等级仍按原网格计算。旧版本继续执行原多样性审计。

验证记录（2026-11-04）：235个不同测试已分组通过，其中新阶段组件28项。覆盖阶段划分、真实父节点方向、首轮独立窗口、阶段焦点、末轮待复查、旁支改善/失败/证据重开、重复数组修正、条件对齐评价、五轮预算及恢复、旧搜索协议和release哈希。三个SKILL.md通过skill-creator格式验证，2.15.0与2.14.0构建校验通过。

本地验证使用已有guidance214-tests环境。扩展回归曾遇到Windows长临时路径和缺少FLOWR导入路径；改用短测试目录、在PYTHONPATH加入已有tmp/flowr_root_scnet_source后完成验证，未修改相关分子逻辑。主回归先通过222项，随后包含环境失败用例的dynamic_matching_jump模块18项全部通过；两组去重后覆盖235项。

结果解释：这些测试证明确定性接口、预算与行为约束，未调用线上模型或运行新的GPU分子实验，不证明新策略的科学收益。
