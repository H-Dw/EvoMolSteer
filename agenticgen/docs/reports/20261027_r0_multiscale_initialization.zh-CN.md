# 用首轮多 scale 实测结果初始化后续迭代

2026-10-27，Asia/Shanghai。用户明确要求：根据第一轮 R0 的多 scale 测试结果设置后续迭代初始 scale。当前实现策略为 `teacher-r0-multiscale-v2`；实验仍暂停。

## 核查结论与纠正

上一实现 `teacher-local-scale-v1` 存在偏差：虽然按教师分开读取标定数据，却额外要求起点严格位于范围内部，选择了 6pyy=128、3w54=181.0193。这一条件把首轮实测优选值降档了。现已撤销，不能再把“给双向动作留空间”作为更换初值的理由。

磁盘中的实际命名需要区分：首轮多尺度粗扫、细扫、窗口测试和全人口验证在 `calibration/`；`R0/<target>/` 是当时选定常数后的单尺度基线，各50次，两个教师的旧 R0 均为181.01933598375618。它不是另外一份包含多个 scale 的测试集合。选值依据是首轮多尺度的 **full 阶段、同教师、每配置50次** 的常数结果；不能混合粗扫10次和细扫20次的指标，也不使用后续 UG 成绩反推初值。

范围和初始化排序分别计算。现有经验范围仍为6pyy的90.5097–181.0193、3w54的90.5097–256，边界依据及局限见此前[逐教师范围报告](20261027_teacher_specific_scale.zh-CN.md)。若未来首轮优选点与经验风险范围冲突，明确停止报告冲突，不暗中换成次优尺度。位移增长10倍的规则仍只是工程启发式，不等于分子质量或数值稳定性保证。

## 后续迭代如何使用

`scale_domain.py` 记录初值、原测量ID和哈希、原C/gap、规则，以及范围内其他首轮实测常数的ID。初始点排序与范围判定独立，解析域时允许初值等于上下界。

`bootstrap.py` 只读核验初始测量和补充锚点：完整full结果哈希、教师身份、每组manifest和COMPLETE回执、records哈希、50个原始种子/槽位/node_id、aggregate与首轮结果一致性。测量ID保持 `calibration/full/...`，不伪造为新 R0 或 UG 结果。初始测量置于history第一条；其余范围内的实测常数可作为明确的行动锚点。每个配置只出现一次，复用不算新尝试或独立验证。

`pipeline.py` 每个后续版本都从这份首轮证据建立初始history，第一条严格对应教师的初始scale；然后才追加当前版本产生的实测行动。最终分析、Prompt锚点枚举及离线恢复回放使用同一history。不会重新引入其他UG版本的动态记忆。

边界上的初值可能无法直接产生增强或重分配动作。代码先按原行动契约枚举少量合法选项，确认该分支存在两个不同、未测、未越界选项。若首选锚点不满足条件，则从已核验history中显式选择其他实测锚点，并向LLM提供 `default_anchor_reason`。这只是分支行动锚点变化，`domain.initial` 和初始测量ID保持不变。若所有锚点均没有两个合法选项，停止，不扩大范围、不补样、不要求LLM反复搜索不可能的动作。

第一轮的具体行为是：6pyy初值181.0193，增强/重分配分支可使用实测128作为锚点；3w54初值256，相应分支可使用实测181.0193。它们必须明确报告实际anchor_id和尺度变化，不得把这些分支锚点称作新的初始化值。减弱分支可以从实测优选初值开始。

物理起点仍是共享R0的step10前分子状态，和“选择哪个实测schedule作为行动锚点”是两件事。此修改没有覆盖旧R0、重建基线或执行配置迁移；已有UG05仍绑定旧协议，不能通过更换域绕过manifest与预算检查。
