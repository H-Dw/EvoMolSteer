# Revision and adoption record

Maintain a version update log outside loaded instructions with: experiment scope and source hashes; parent release; principal problem and affected decision stage; decisive evidence and counterevidence; changed modules; exact edit; expected behavior; observable falsifier; protocol compatibility; abstract transfer hypotheses and their source provenance; actual validations; limits; and adoption status. Link the configuration lineage separately from the skill lineage. Preserve rejected interpretations and historical versions without treating them as active instructions.

First establish whether the failure arose because relevant data were absent, an available fact was misread, a legal action was misconstructed, selection ignored a constraint, or execution/evaluation deviated. Fixing a controller feature requires a separate code change and its validation; instruction wording cannot pretend to implement retrieval, abstention, recovery or a different metric ranking.

Center the revision on one problem even if consistency requires changes across one to three role modules. Avoid unrelated prompt experiments in the same revision. Check archived pre-decision cases for legal identifiers/actions, duplicate avoidance, faithful history use, counterexamples and fixed output shape. Do not use later outcomes as earlier inputs. A static review is not an actual model run; an actual model run is not a measured molecular-quality gain.

Create a new destination exclusively. Verify the parent's hashes before and after; reject an existing destination rather than clearing, overwriting or incrementally repairing it. Finalize a manifest of source/output hashes, parent and validation records. Future revisions copy into another new version. A release being present or pushed does not make it active: only a future authorized experiment explicitly binds the accepted version. Do not change the running experiment's source binding or existing default route silently.

Separate proposed, statically checked, behaviorally evaluated and process-accepted status using actual evidence. Measured reduction of illegal or duplicate actions, or verified correction of evidence handling, may support process acceptance without proven geometry gain. Report the corresponding denominator and observed scope. Format validity alone does not prove such behavioral improvement. Molecular best remains determined by the existing compatible measurements and ranking; never promote it based on prompt quality, reset counters or erase failures. Later scientific validation uses only future authorized experiments and the receiving target's calibration, legal actions and fixed panel.

If reviewing the external RSI method itself, identify its own observed review defect and create a new version of that skill; do not overwrite it or infer unlimited permission for recursively calling itself. No supported change means a truthful no-revision record, not a fabricated lesson.
