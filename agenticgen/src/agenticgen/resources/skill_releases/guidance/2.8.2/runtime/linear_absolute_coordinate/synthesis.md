按超过当前最优的探索机会选择已有提案，最多达到外部数量上限。三种强度表示参数跳跃距离，不是增加、降低、再分配三个方向，也不是对照、处理、验证三个实验角色。

不要要求提案给出生成动力学解释、单窗口证据链、消融价值或反证条件。未测但可能更好的路径可以入选。比较机会接近时优先更广的联合调整或更激进的路径，避免因为小步方案更容易论证而反复退回极窄邻域；仍不能为了激进本身挑选已预期明显更差的方案。

可以选择多条同强度或同方向方案，不要求每类都选；只要一条值得测就只选一条。剔除相同实际配置，禁止以新的名称重复生成。没有有希望的合法路径时保持当前最优或请求具体范围取证，不添加模型调用来凑齐名额。

真正结果由采样和冻结指标决定。假设不是成绩，20 候选不能替代完整人口排名。既有最佳包含标定和正式历史，不能为了宣布迭代有效而替换成较差正式组。

只选择现有提案身份，不重写或拼接数组。选择理由只说明潜在改善路径与未知，不组织消融、反证或机理总结。按给定 schema 通过 submit_final_response 提交；轮数和预算由外部控制。

说明文字 reason、improvement_reason、uncertainty 每个字段最多 3000 个字符（按字符计，不是 token）。足以表达探索落点、选择理由和不确定性即可，无需凑满。证据 ID 必须逐字复制实际已测身份或已读回执；较长文字不允许虚构证据。模型 token 与调用预算由外部配置控制，保持不变。


## 最终选择的机器接口

最终答案必须是一次单独的 `submit_final_response` 工具调用。参数完整包含 `decision`、`selected`、`reason`，先确定并填写 selected 数组，再写说明。正文中提到方案身份不能代替 selected；禁止省略、null、字符串或让执行器根据说明猜选择。

- `propose`：selected 包含 1 到外部上限个 candidate_ids 中的真实提案身份。
- `request_domain_evidence`：同样显式选择真实身份，且每项确为合法范围请求。
- `hold`、候选为空或 no_future_execution=true：selected 必须显式为 []。

保持的完整参数示例：`{"decision":"hold","selected":[],"reason":"当前没有值得执行的合法新提案。"}`。非保持时必须换成自己选择的真实提案身份，不能照抄示例保持，也不能编造身份。选择多少由潜在优化机会决定，不为填满数组选预期明显更差路径。

提交前检查：字段齐全；decision 与 selected 是否一致；身份逐字来自候选列表、互不重复且不超上限；reason 在3000字符以内。这个检查只验证接口，不增加消融、机理证明或新测量。如果收到格式反馈，唯一修正必须重交完整工具参数，不只补一个字段；不得修改测量或发起新采样。不要以普通文本/JSON正文结束会话，也不要把最终提交与证据工具放在同一个调用批次。
