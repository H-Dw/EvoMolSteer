# 分析模块输出审计与精简策略（2026-10-04）

结论：原分析目录偏大的主要原因是衍生数据展开、重复缓存和默认保存全部诊断明细；不能把全部体积理解为新增的科研信息。应当优化输出策略，同时保留完整统计推断和可以重建明细的原始输入。

本报告审计的是已完成的 main1000_w050 全轨迹版本。核对期间，共享源码被另一项工作改成了“仅实际重采样节点”口径，因此优化验证移至独立源码副本。本报告的减少比例固定原有 100 个积分步、255 个特征和统计定义，没有混入科学范围收缩的收益。新口径的最终集成尚未在本任务中确认。

## 1. 为什么分析数据比结构数据大

25 个原子的坐标只有 75 个 float32 数值，约 300 字节；同一结构向 84 个受体残基区域计算特征，得到 255 个 float64，约 2,040 字节。特征提取展开了多个几何观测，不保证文件体积比输入更小。原结构文件已经使用 NPZ/gzip，重复类别、零值和共同结构又容易编码得很小，因此两者大小不能直接解释为信息量。

原提取程序对每个节点计算 current、predicted endpoint、proposal 三种表示，形成 900,000 行；原分析配置只使用 predicted_endpoint。并行提取的 20 份分片合并后仍保留，造成第二套特征副本。大量变化率也由特征与谱系直接推导后再次永久保存。

| 原输出 | 实测 MB | 作用与审计判断 |
|---|---:|---|
| 主特征表 | 2080.79 | 三种表示全部展开；当前分析只消费其中一种 |
| 20 份工作分片（含特征及辅助文件） | 2106.20 | 并行工作产物；与合并结果重复保存 |
| 逐父子节点 × 特征变化率 | 451.33 | 207,900 条边 × 255 个特征；没有被后续统计或证据构建读取 |
| 逐步长选择分解 | 59.81 | 1,071,000 行；阶段汇总需要计算，但无需默认保存所有行 |
| PCA 节点投影及逐边速度 | 21.59 | 可用于详细图和诊断；正式证据使用基底、载荷、阶段质心及变化率 |
| 6 张批次级 CSV | 67.30 | 必须保留的统计复核依据，但长特征名和分组标签重复写成文本 |
| 实际 LLM 证据包 | 0.198 | 已有限额；并没有把 GB 级特征表全部传给 LLM |

20 个分片彼此不重复；重复发生在“分片合计”与“合并主表”之间。逐边变化率不是错误数据，只是从已有输入可再生、且当前下游不直接消费的诊断明细。

## 2. 是否存在无效或冗余特征

对 discovery 的 210,000 个预测状态审计：255 个特征没有整列恒定或全缺失；最高缺失比例为 0.00810%。所以没有依据直接删除大批特征。
在 discovery 的 unguided 背景完整观测上，51 对特征满足 |r|>0.99，232 对满足 |r|>0.95。相邻区域、距离与接触指标会相关，但相关不等于生物学含义可互换；本轮没有据此删特征。PCA 保留用于检查共同变化方向。
更明确的低信息对照是同胞差异：3,060 条汇总最大绝对效应为 5.21e-17，全部小于 1e-12，且没有校正后显著项。克隆的预测状态一致，这些数值属于数值零。应将其标为同胞一致性/零效应对照，不能当作优势区域证据。
不显著结果、样本批次不足产生的未知显著性、化学失败、未选中和绝灭分支各有不同含义。不能为了节省空间只输出显著结果或成功分子；那会改变证据分布。原分析定义和全部多重检验结果在本次试验中保留。

## 3. 已实现的输出策略

1. 原始生成结构、评分、谱系、概率和续跑状态继续作为可追溯输入，保持原文件。
2. 特征缓存只计算配置实际要求的表示；终态校正和既有 LLM 证据需要 predicted_endpoint 时自动保留它。全部节点和特征仍参与既定分析，不采样删节点。
3. 并行分片完成合并并核对后，清理本轮创建的临时文件，保存分片校验清单。不会清理旧结果目录或原始结构。
4. 完整保留各方法的批次效应、阶段效应、变化率、置信区间、p/q 值、PCA 基底/载荷与成功失败统计。批次表使用无压缩 Parquet 和类型化列/字典索引，保留 float64；小型正式汇总继续保留 CSV。
5. 趋势按批次计算并汇总，不在内存中堆积全部逐步字典；仍检查全部 1,071,000 个分解事件。父子变化率保留每批/阶段/特征的均值、标准差、范围、有效边数及跨批推断。
6. 逐节点 PCA、逐边变化率和逐步选择分解默认作为可选诊断输出；audit 模式可重新输出。PCA 拟合仍使用 discovery/unguided 的同一背景，末端校正仅读取需要的最后节点。
7. 特征缓存分工作态与归档态管理；数据值和摘要相同，只改变是否保留可重建缓存。

阶段汇总不能单独反推出逐节点明细。再现明细依赖原始结构/谱系、配置、代码和依赖版本；本策略不是把汇总表宣称为逐节点数据的无损编码。

## 4. 实测结果与速度取舍

| 比较范围 | 原 MB | 新 MB | 减少 |
|---|---:|---:|---:|
| 正式分析结果 discovery/ | 618.58 | 29.82 | 95.18% |
| 完成目录，归档态（缓存已清理） | 4818.18 | 41.17 | 99.15% |
| 工作态：正式目录＋单一特征缓存 | 4818.18 | 约 699.74 | 约 85.48% |

工作态数字是已测正式目录与已测缓存大小相加；日常需要重复分析时建议保留这一份缓存。归档态适合暂时不重算的结果，后续重算前需要重新生成缓存。缓存重建只计算几何，不重新运行 FLOWR 分子生成。
6 张批次级表由 67.30 MB 文本转为 12.57 MB 类型化列，没有启用熵压缩或降低精度。原 CSV 使用 12 位有效数字输出，新的二进制批次表保留更多浮点有效位。
目录比较还包含辅助表和证据请求；原目录有一些历史 LLM 响应和奖励检验文件，本轮没有重调 LLM。严格可比的正式分析结果单独列在第一行。原旧分析目录仍保留供复核，因此没有宣称已经从旧目录释放 4.8 GB。

## 5. 验证结果

- 18 个主要结果文件全部与原版逐字节一致，包括富集、差异、PCA、趋势、终态比较及阶段变化率。
- 6 张批次级表逐项核对，均在原 CSV 精度范围内一致；没有按显著性过滤行。
- 主实验 LLM 包中的 134 条证据和 60 个目标区间一致，仅路径和数据集来源标识不同。没有重跑 LLM 推理来掩盖数值变化。
- 全部选择分解仍计算并验证，最大残差 2.17e-19。
- 两批真实原始数据重新提取 30,000 行、282 列，与既有预测状态特征一致。缓存清理后从原始轨迹再次构建，文件 SHA-256 完全相同。
- 独立副本的 13 项测试通过，覆盖统计结果一致性、精度、无压缩格式、缓存所有权和安全清理。
- 两批测试的旧 LLM 包来自更早的 schema，因此没有宣称其整个包逐项一致；完整主实验已单独通过严格证据等价比较。
- 共享目录改动造成的两次混用版本运行已标记为失败并排除，其新建的大型临时缓存已清理。最终数字仅使用独立副本的成功运行。

## 6. 文件与复用

- 成功的紧凑结果：results/main1000_w050_compact_v1_verified/。
- 旧输出审计：test/analysis_output_policy/audit_original.json。
- 完整结果比较：test/analysis_output_policy/full_comparison.json。
- 两批原始重算及缓存校验：test/analysis_output_policy/fixture_roundtrip.json。
- 冻结实验源码：test/analysis_output_policy/implementation_v1/。
- 源码校验清单：test/analysis_output_policy/implementation_manifest.json。

调用独立副本时使用 implementation_v1/run_snapshot.py 作为入口，避免导入正在变化的共享代码。该入口之后接原脚本名和参数，例如 run_pipeline.py 或 materialize_feature_cache.py。完整运行配置已经保存在成功结果目录的 config.json。
工作态设置 output_policy.retain_feature_cache=true；归档态设置 false。write_node_details / write_step_details 控制诊断明细。原始无 output_policy 的配置继续保留 audit 行为。
最终建议：把结构数据作为长期底稿，把几何表作为单一工作缓存，把完整统计结果与有限的 LLM 证据作为正式交付。当前另一路“仅重采样节点”的科学范围变更应独立验证，不能与这次输出策略的等价比较混为一项改动。
