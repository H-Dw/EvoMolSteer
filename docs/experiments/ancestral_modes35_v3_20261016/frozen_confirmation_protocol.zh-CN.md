# R34/R35 冻结确认与对照复用

前33个开发条件结束后，按已登记的“最高基本合格终态分数”冻结同一尾部分支；平均值守卫下的 incumbent 另存。确认过程中不改奖励、点集、时钟、权重或选择标准。每池四个预先指定批次、每批50，两个池共400个引导样本及400个匹配无引导样本。全部 seed=42；它不是多随机种子或新靶点验证。

为减少重复加载，每个确认批次在同一个 FLOWR 进程内顺序执行无引导与冻结奖励，各条件仍单独克隆相同50个初态并重置随机流。粒子不跨条件混合，没有 SMC。已有匹配控制优先复用；仅缺少的控制与新引导一起执行。两种条件完整下载并验证后，配对程序再次核对初态、槽位、checkpoint、上游原生代码、seed 与全部已解析 native options。实际控制路径写进结果，不能假定固定缓存目录。

此改变只合并模型加载/传输，不改每条件的 batch size、100步积分、控制域、后缀或奖励。实际新增的分子尝试数包含两种条件；不把控制样本伪装成优化轮次。八组确认只需要八次模型加载，原方案需要最多十六次。

统计按独立初态批次汇总：每池四个批次均值作 bootstrap 单位，避免把200个粒子当作200个完全独立实验。两个池都通过才登记预定确认成功。最大值、尾部产率、失败与评分覆盖、PB 和两阶段 MMFF 各自报告，不因看见某一池结果而重新调参。

原 Steer 的 CLI 参数中 SDE=False、coord_noise_scale=0 不是最终执行值；原 `run_lineage.py` 在加载后显式覆盖 SDE=True、coord_noise_level=.2，与本轮真实配置一致，来源与哈希见 `original_runtime_override_audit.json`。保留原始配置，不据 CLI 默认值制造协议差异。

结构诊断使用同一当前 PoseBusters dock 和受体，原 Steer 旧 PB 输出仍保留；已发现原最优 F 的旧检查未通过，而当前版本复测通过，因此不能把跨版本旧失败用来声称新方法超越。能量统一用先固定重原子优化H、再释放全分子的 MMFF94s 局部松弛/重原子代理，不使用旧的H初始放置应变作直接比较。
