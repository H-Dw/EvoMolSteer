# R26 前的 API 交接修正

R24、R25 已执行的程序、评分、谱系和 API 原文不修改，也不重跑来替代负结果。

审计发现两种不合格解释：把旧配置中不再有效的 pseudo-Huber 参数仍写成实际奖励项；忽略 RMS 归一化后的历史对比减力、直接套用 parent 的实际剂量。旧 LLM 文字审阅没有可靠识别这些问题，因此不能作为执行一致性的唯一保证。

修正采用确定性接口，而非要求 LLM 重写更多配置：

- 数值身份和 API operative-only 视图复用同一有效参数注册逻辑；未启用的匹配记忆、类型通道和曲率不再进入有效算子描述。
- Analyst 绑定科学机制、时钟、父分支及源证据。Designer 的真实 API 只返回六项：选项 ID、假设组、parent、证据、科学理由和否证条件。
- 编译器依据 ID 从合法选项中提取函数，生成公式、参数差异、导数路径和归一化后剂量对象。返回值与原始 API 文件及其 SHA 绑定，拒绝注入新奖励字段或替换 parent。原始响应与编译后交接各自保存。
- 移除重复发送的历史正文，历史保留每轮指标和关键响应，完整记录另有不可变引用。Designer 只接收 Analyst 引用的证据；所有父分支的评分仍保留，无选择性隐藏失败。

真实 DeepSeek flash 验证：旧验证中一次 Designer 输入为 111,065 tokens，且 `derivative_path` 连续超过字符限制，最终接口失败。新验证输入为 40,627 tokens（降低约63.4%），输出546 tokens，零格式修复；六字段提取与确定性算子绑定通过。它证明接口响应与数学说明的一致性，不证明新提示词已经改善分子质量。

开发池的最好尾部仍为 R02 的8.699415，与原 Steer8.704806相近。平均值守卫与尾部候选分别保存。后期回访允许已有机制的晚期剂量分配、±5%物理强度和不超过配置点数的联合锚点；不改变最终冻结新池确认。
