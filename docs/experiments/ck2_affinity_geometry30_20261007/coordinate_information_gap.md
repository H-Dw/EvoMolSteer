推荐的验证顺序：

1. **先做表示/位姿信息审计。** 在原始14发现批、同一50节点比较24/74维近邻与完整点云距离，分别报告固定框架、质心差和proper rigid alignment后的内部差异。可统计纯feature Jacobian的秩，不需FLOWR调用；当前只知24标量的秩上界24，尚未测实际秩。若phi近邻并不丢失关键几何，就不应直接堆字段。
2. **补endpoint无类型局部有向矩。** 沿用既有20个landmarks，计算局部一阶向量和svec二阶中心矩，并记录未归一化mass、有效槽位与退化支持。旧current/proposal实现可复用，主状态须明确改为endpoint。方向字段需经过global centroid/cov或trace对照；若效应只是共同平移，不能称区域独立优势。梯度要明确包含连续权重的导数，或明示固定anchor的条件偏导。
3. **再检验跨区域关系。** 对预声明小型landmark邻接图计算同槽共占据、区域相对中心或跨区pair核。已有径向边际和区域内pair不等同于跨区共同安排；但joint prototype也已保留一部分关联，不能夸大为完全缺失。
4. **最后扩展真实父边协同位移。** V3目前只有landmark_00_softmin得到历史支持。新候选可分解父子forecast的刚体变化、内部残差和区域位移向量/交叉矩；这不是物理速度，也不能据全窗负值硬指定每步−x/−y。先去父重复、再做root与batch敏感性对照。

flow matching语义必须保留：Y_t是模型终点预测，X_t是当前噪声态，proposal是原生步后的状态。记录head来自同forward latent，不是独立h(Y_t)。VJP在旧X_t、固定self-conditioning和类别下求导，原生SDE/类别更新后注入；未来cond及类别仍会改变。因此端点局部fit、实际x_.5 fit和终态分数可分离。局部端点奖励经模型Jacobian还会作用于其他输入坐标，不能据字段名称保证“其他区域完全自由”。

精简报告没有全程cond/Jacobian或注入后fresh endpoint；Trace源码只说明可存有限restart快照，本次未读取原始restart包。不能由坐标差反演Jacobian，不能把旧状态g·Δx当实测新奖励。如需新forward审计，必须单独列成本和授权，不混入零额外调用声明。

全部新挖掘建议仍以14批为推断单位、50节点全窗分析，不切.1 bins。把即时选择富集、同刻head关联、边界存活和去重父节点后的gain分开，统一多重检验并保留null/coverage。level曲线与edge增量使用不同的明确定义；时间导数不是空间力。只保存batch×time向量汇总、全窗效应/CI/p/q、精确节点及fidelity和来源hash，流式丢弃粒子展开；结构原件保护不删。
