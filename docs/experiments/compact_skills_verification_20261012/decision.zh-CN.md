## 事前验证方案

1. 六条空白上下文 Analyst→Designer 真实 API 链，两种等义任务表述，各三条。所有链读取同一冻结证据。保留实际指令、来源哈希、请求、工具观察、回答、确定性提取和编译回执。
2. 在生成结果出现前，以数值程序众数选择配方；并列优先给定 M2，之后按哈希稳定排序。不得按新结果选幸运链，也不得强制产生奖励改动。六链不是六套独立分子样本。
3. 新生成 400 个 guidance 尝试：8 个固定批次，每批 50，批次 6376–6383，主种子 42，与旧无引导/M2 的初始随机状态逐项核对。100 积分步，由证据确定引导支持，支持之后完成原生推理。只生成 guidance，不再生成控制、不运行 Steer。
4. 最新用户明确要求再生成验证；即使最终程序与 M2 相同，本次只额外重复这个候选队列以检查新工作流的部署可复现性。相同随机输入的重复不是新增独立证据，不能把两个 400 队列合并成 800。
5. 直接复用 400 无引导、400 M2 与原始 1000 Steer。报告所有尝试的预测 pIC50、覆盖、有效率、PB、MMFF 应变及固定高亲和力尾部。无引导/M2 为配对比较；历史 Steer 独立且在线预算不同，不用均值点估计宣称统计优越。
6. 本地先提交和推送，远端拉取对应提交后只执行 FLOWR；验证传输后清理本次远端临时结构，保留一份本地压缩终态结构及精简报告。保护原始 Steer、checkpoint 和固定对照库。
