# 生成配置的原文件哈希与内容哈希

第 18 轮真实数据的审核 smoke test 暴露了记录接口的格式假设错误。生成 controller 使用保持插入顺序、无尾换行的 JSON 写法；源码绑定工具随后使用排序并带换行的写法。原 `generation_config_sha256_before_binding` 记录前一种文件的原始字节 SHA，审核器却尝试从后一种记录重算排序 JSON 的 SHA，两者不应相等。这项失败不能说明生成参数被修改。

修正仅涉及完成推理之后的 metadata 与独立审核器：同时保存原文件 SHA 和 `generation_config_canonical_sha256_before_binding`。后者从绑定前的已解析配置，以明确的排序、UTF-8 和 LF 序列化计算；审核器用它检验原配置字段的内容一致性。原文件 SHA 保留并检查格式，但不会声称从已排序记录重建了原文件字节。

第 18/19 轮旧记录没有事后补写。严格冻结确认阶段使用新字段；缺少新字段的历史记录被标为此项内容校验证据不足，而不是模型数值修改。第 18 轮的公开数值结果、原始配置、推理 commit 与已发布 retention 均保持不变。

修正经过绑定工具 8 项测试和完整性审核器 30 项测试，包含真实第 18 轮的旧格式检测、原 controller 序列化格式、修改字段与错误哈希的拒绝。它不改变冻结的 54 份数字源码、奖励函数、随机数、模型前向次数或任何 affinity 标签。最终确认报告在新进程中重算，避免审核器的进程缓存影响结果。
