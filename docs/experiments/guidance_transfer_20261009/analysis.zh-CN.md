# R26 / R11 的 Steer 数据依赖与新靶点迁移

本次为源码、实际 Agent 请求/响应、参考库及历史版本的只读分析，没有修改 Skills、奖励函数或正在运行的生成任务，也没有开展新靶点实验。源文件校验值和直接核对结果见 `source_audit.json`。

结论：可以迁移的是分析方法、受约束设计流程和 FLOWR 坐标控制接口；当前 R26/R11 的具体奖励携带 CK2 靶点的经验空间先验，不能直接视为其它靶点的零样本奖励。无 Steer 的结构驱动方案有研究潜力，但尚未获得新靶点亲和力提升的实证。

## 实际使用的 Agent 与工作流

历史 R26 的原始生成提交是 `9a6f80a`，当时采用坐标分析、亲和力优先与端点回拉的较长指引。随后 Skills 消融将活动入口精简为 `skills/analyst/SKILL.md` 和 `skills/designer/SKILL.md`；旧长文归档到 `docs/experiments/skill_ablation_20261007/legacy_skills/`，若干旧 Skills 现在只是兼容跳转。不能用今天的短文反推历史 R26 最初完全没有靶点特定指引。

精简后的部署 Designer 实际选择 `retain_existing`，保留注册的 R26（program_20）且无参数更新。其依据包括 Steer 区域统计、趋势函数、谱系支持、完整教师坐标的信息审计，以及先前配对生成质量记录。它不是重新独立发现 R26。

R11 的实际请求位于 `docs/experiments/flowcompat30_20261009/agents/branch_phase_v2/`。Analyst 使用通用 Analyst、flow-compatibility 和 supplemental 三段文本；Designer 使用通用 Designer 加相同两个补充模块。接口绑定 selection_innovation、flow_compatibility、branch_mutation 的真实执行 receipt，以及额外 multi_depth_mutation 证据。Designer 接收已验证的 Analyst 响应并绑定其 hash，再从公式注册表选择 `branch_mixture`。

原始 Designer 建议的虚拟模式质量为 0.1；R11 实际使用 0.025，来自后续逐轴工程调试。R11 配置明确记录该更新并非一次新的 LLM 调用。多深度区域分析提出的 region17/18 假设在这套实际 R11 请求中保持待实现，R11 数值上仍使用 lag-two 的完整联合分支方向，未把那些假设全部转换为区域奖励。

目前 Designer 主要选择注册公式与有限参数，不会直接执行任意 LLM 生成的奖励代码。新数学特征和新公式需要先实现为确定性工具/模块、加入注册表并验证。schema 合规、hash 对应、机制实际响应和最终生成收益是四项不同问题。

## 哪些依赖 Steer，哪些方法可以独立复用

|指引/操作|当前所需信息|没有新靶点 Steer 能否使用|
|---|---|---|
|核对表示、单位、时间支持、目标优先级|任务与模型执行定义|可以，属于通用契约|
|受体 landmarks、点对核、质心、二阶形状矩|受体/口袋、待分析坐标；现有 landmark 定位还使用参考配体|可以计算特征，但不能凭计算结果宣布亲和力优势|
|高低分富集、差异、与在线 affinity 的关联|同一事件内的分子、坐标与评分|需要目标相关样本；原生试采样可提供另一种数据，但不能伪装成 Steer 选择事件|
|连续窗口趋势、变化率、批次置信区间、BH 校正|跨时间、跨批次观测|方法通用；没有观测不能填出函数或显著性|
|选择压力、存活、复制与淘汰的分解|真实选择概率、父子索引、复制数量|强依赖选择过程，静态口袋不能替代|
|共同祖先的优势空间变异|可观察共同祖先、不同立即父节点、坐标创新与评分变化|当前 R11 强依赖 Steer 谱系；无选择的其它分支实验应使用独立语义与工具|
|不将复制视为独立样本、不补淘汰分支未来|数据观察与缺失语义|原则通用；用于检查数据，不能创造缺失信息|
|保留多模态联合空间背景，避免局部目标互相冲突|公式与候选空间假设|原则通用，但当前的实际模式来自 CK2 教师|
|端点奖励经真实 FLOWR Jacobian 回拉|预训练 FLOWR 的当前前向与可微标量奖励|可复用，不需要历史 Steer；它传递给定奖励的梯度，不自动提供 affinity 梯度|
|数值导数、零剂量等价、真实位移、窗口外零注入|模型/控制器及运行记录|可复用；质量收益仍需生成评价|
|平坦结果先核实有效剂量，负结果审查奖励/特征|实际新实验反馈|不需要 Steer 参照也能比较 native/guided，但需要新靶点实验结果，属于反馈适配|
|亲和力优先、应变次级、不以图改变判定失败|任务定义与质量记录|可复用；排序不能代替质量计算|

关键边界是“能计算某个描述符”和“知道其有利变化方向”。例如口袋占据可以直接计算，但占据越大并不普遍意味着亲和力越高；过度填充或整体收缩也会产生看似改善的几何数值。高分/低分的经验符号、权重与阶段支持来自额外目标信息。

## 实际奖励中携带了什么先验

两套库都来自发现批次 0–13，有 50 个评分节点（0.00–0.49），每节点 28 个教师点云、每点云 25 个原子，学习支持为 [0,0.5]。库内保存原始受体及配体的 SHA256。实际控制器继承的输入核对会拒绝受体/坐标系不匹配；移除核对并不能让 CK2 坐标获得新靶点含义。

R26 在当前端点预测 \(Y_t\) 附近选择四个几何匹配的教师，固定 Hungarian 对应及先验：

\[
\pi_j\propto\exp[-q_j^{anchor}/4+2(s_j-\bar s)],\qquad
R_t(Y)=\tau\log\sum_j\pi_j\exp[-\rho_\delta(q_j(Y))/\tau],
\]

\[
q_j(Y)=N^{-1}\sum_i\|Y_i-T_{j,\sigma_j(i)}\|^2,
\qquad \rho_\delta(q)=\delta^2(\sqrt{1+q/\delta^2}-1).
\]

其中 \(T_j\) 和 \(s_j\) 都是 CK2 Steer 中记录的端点与在线评分，\(\tau=0.5\)。推理时不再调用历史采样器，但仍读取由历史样本构成的经验先验。没有新增亲和力网络，并不意味着没有目标特定信息。

R11 保留 R26 原始教师，增加

\[
T'_j=T_j+a_jd_j,\quad a_j=\min(\text{observed branch RMS}_j,0.2\AA),
\]

\[
p_{j,0}=\pi_j(1-0.025e_j),\qquad p_{j,1}=\pi_j(0.025e_j).
\]

方向 \(d_j\) 是同祖先高分教师减较低分自然分支的联合空间差，再归一化；\(e_j\) 来自真实 lag-two 分支资格和非零支持条件。R11 没有额外启用 region_weight_mix，因此数值上没有将多深度 region17/18 假设写入区域权重。缺失早期祖先和不合资格分支退回 R26，不能用 LLM 猜出字段填补。

两者均使用 \(g_t=J_{F_\theta}(x_t)^\top\nabla_Y R_t(Y_t)\)，保持自条件、对应与先验在本次导数中固定。可迁移的是这一计算路径；\(\nabla_YR_t\) 仍取决于目标先验。当前 0.33 的原生 RMS 剂量、0.025 的模式预算、温度与控制上限是实测工程参数，不是对所有靶点成立的常数。

## 三种不同的“零样本”含义

|任务设定|本项目应使用的表述|判断|
|---|---|---|
|保留 CK2 的教师、评分和分支方向，只更换 target 文件|旧经验奖励直接跨靶点迁移|当前不支持，也没有有效性证据|
|新靶点没有 Steer，先生成少量 native 轨迹并利用其正常前向/最终评分设计奖励|无 Steer 的少量样本适配|有可行性；仍使用新靶点样本与反馈，不是严格零样本设计|
|设计前不使用新靶点生成轨迹/亲和力反馈，仅根据口袋结构、允许的结构注释及预训练模型提出奖励，并冻结后测试|结构条件下的零样本奖励设计|值得研究；当前没有实现/验证这一分支|

零样本不等于零先验：预训练模型、一般化学知识和允许的靶点结构仍提供信息。目标若有已知共晶配体或药效团，它也是靶点特定先验，应明确报告。冻结设计之后生成评估样本是必要检验；只要不用这些结果重新设计，该评估不等于利用测试标签进行适配。

单独的未类型化坐标与口袋空腔不能识别未知靶点的亲和力最优方向。可微公式的梯度可以精确计算，但没有目标质量信息就不能证明它也是 affinity 改善方向。LLM 可以从结构知识提出假设、编排工具与程序，不能把未观察的富集、阶段趋势或效应方向写成已经测量的事实。

## 无 Steer 分支可以如何设计

建议保留通用 Analyst/Designer 与数值控制模块，同时新增独立结构驱动工具和证据类型，使用 `evidence_mode=steer_trajectory`、`native_pilot`、`structure_only` 区分数据来源。这是规划，尚未更改现有执行合同。

结构驱动 Analyst 可先计算口袋可达空间、曲率/方向、受体排斥场、暴露程度、空间可匹配的供受体/疏水/电荷位点，以及可选已知配体的坐标药效团。需要统一质子化、残基缺失/金属等输入语义。输出“结构上可行的候选区域”，而不是“已经富集的优势区域”。局部能量字段可以按固定一般参数构造，但不能冒充经过实验验证的亲和力机制。

结构驱动 Designer 可选择一类无需教师的端点奖励，例如：

\[
R_{struct}(Y;P,a,b)=w_c C_{compat}(Y;P,a,b)-w_r E_{rep}(Y;P,a)
-w_g D_{internal}(Y;a,b).
\]

\(P\) 是新受体结构，\(a,b\) 是当前端点预测的化学上下文，固定于一次导数；优化变量仍为坐标，原生原子/键通道自由演化。\(C_{compat}\) 表示有类型、方向及覆盖约束的空间兼容性，\(E_{rep}\) 是平滑排斥，\(D_{internal}\) 是防止坐标塌缩的几何诊断/约束。权重与外部剂量需分开：现有控制器归一化梯度，仅整体放大奖励通常不会加大真实注入。

这是一类待注册与验证的假设，而非当前可运行的新奖励。重点应该是目标相互作用兼容性和 affinity 的检验；应变仍是次级目标。给新靶点施加更强的一般应变最小化，不一定提高其预测 affinity。可使用已建立的原子类型相互作用或网格思路作为程序依据，但不能把 AutoDock Vina 的直接调用假设为现成的 Torch 可微奖励。

[AutoDock Vina 1.2.0 原始论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC10683950/)提供了类型化相互作用与外部网格的实现依据，也报告不同靶点上评分表现存在差异。因此物理评分提供可探索的目标信息，不能保证每个新靶点的亲和力收益。

奖励应满足共同刚体变换下的不变性，采用受体局部背景或相对距离，支持可变原子数并避免固定残基编号。原有世界坐标 shape_yy 的有利符号不能机械迁移。接触数、shape 等字段要防止数量和整体压缩的伪改善，并保存重叠区域与周围背景的兼容性。

结构模式没有学习到的时间支持，应单独声明执行窗口/策略及来源；不能把 CK2 的 [0,0.5] 自动当成新靶点经验窗口，或伪造趋势拟合。保留实际 FLOWR 端点 VJP 与原生续推的执行机制，但不要把单一端点均值预测的局部控制称为精确奖励倾斜分布。[On the Guidance of Flow Matching](https://proceedings.mlr.press/v267/feng25s.html)区分了无需额外训练的方法与不同条件下的近似；这支持研究该方向，不构成分子亲和力提升的证明。

## 如何判断是否真的泛化

先冻结来自已有靶点的通用工具、公式与参数选择规则，再在没有设计阶段 Steer/native 反馈的新靶点上运行。分别记录结构来源及预训练可能覆盖的靶点，按蛋白家族/口袋相似性分组，不能把同一家族几个靶点当成充分的广域验证。

比较组至少包括 native、冻结的结构驱动 guidance 和允许使用少量 native 反馈的适配版本；新靶点 Steer 可作为额外预算参照，但不用于零样本奖励设计。相同初始状态、生成数、后处理与预算口径需要一致。评价目标 pIC50 的配对均值、高分尾部与独立化学图，辅以结构合理性、同图应变及独立评分；不得沿用 CK2 的固定 8.2589 阈值。可以事先规定每个靶点用 native 对照的上分位定义尾部，计算后不据此调整奖励。

实现反馈先于效果判断：用盲化 target 输入或字段移除检查 Analyst 输出是否真正响应新受体，再验证 Designer 引用的字段实际进入公式，确认新项改变梯度/位移且零开关等价。正常的生成评估发生在冻结之后；如果失败后利用该靶点反馈调整，应重新标注为目标适配，并另取测试集。

当前同靶点新 400 样本中 R11 相对 R26 的均值差为 −0.000322，区间跨零，说明 R11 增量尚不是稳定的通用机制证据，更不能外推为跨靶点增益。工程可移植、Agent 合理解释与实际亲和力泛化必须分别验证。

## 一处需要纳入后续语义核验的问题

部署 Designer 对 R26 的文字曾采用 `robust_delta=2` 写出 \(\rho_2\)，但真实 pointcloud 路径读取 `pointcloud_delta_A`，该字段未配置时为 1 Å。R26 与 R11 当前都实际使用 \(\delta=1\)，四块 `geometry_block_weights` 在 pointcloud 模式中仅用于描述符/诊断，不控制它的全坐标奖励。源码和已有执行指标没有在本分析中更改。

这不是新的生成质量比较，而是发现了文字与执行语义的差别：hash 绑定可以证明读取了哪份说明，不能证明说明中每一个数学参数都符合代码。新靶点工作流应增加“文字公式—注册字段—实际标量/梯度”的语义核验，避免 LLM 依据未生效字段进行推理。
