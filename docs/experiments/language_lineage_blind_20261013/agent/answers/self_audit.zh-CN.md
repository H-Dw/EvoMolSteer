# 已执行方法的事实审计

本文件只审计 `run_selector.py` 的实际代码行为；没有修改任何排名、回放结果或原 `method.zh-CN.md`。

## 实际解析和使用的字段

脚本对每张卡解析并放入匹配向量：

- current 和 forecast 各自的回转半径、三个固定轴二阶矩、2.5 Å 短程对核、7 Å 长程对核、最短槽位间距；
- current 和 forecast 各自 R00/R05/R15 的高斯质量、局部偏移三元组、3 Å 壳层核；
- “当前到预测终点的同槽位剩余 RMS”“真实父子边的当前位移 RMS”“终点预测修订 RMS”三个 RMS 数值。

三个 RMS 都进入 `vec()` 和 `score()`。因此“只是使用三个非负 RMS量”不正确：RMS 是附加项，主体仍是当前/预测几何字段。脚本没有对 RMS 做符号处理以外的推导；输入本身为非负距离量。

## 实际没有解析或使用的字段

脚本没有使用 current 或 forecast 行开头的“相对参考重心偏移”三元组，也就是绝对/全局重心偏移没有进入分数。脚本使用了区域 R00/R05/R15 的“局部偏移”，这两类偏移不能混同。

脚本没有解析或使用“相对前一 0.01 节点”整段字段，包括所有有符号变化值和变化率：current_Rg 的变化率、forecast_Rg 的变化率、pair kernel 的变化/变化率，以及各区域 mass、局部 dx/dy/dz、occupancy3 的变化/变化率均未使用。

脚本没有使用预测硬标签中的 N/O 槽位数或非零硬键边数，也没有使用任何能量、亲和力、选择概率或质量标签。状态卡的 parent ID 只用于 continuation 的真实子状态资格过滤，不用于几何分数。

## P 路径选择和跨时刻行为

每个状态都与同一 `t` 的五条 P 描述逐一计算分数，并取分数最小的单条 P；因此“最近 P 路径”是逐状态、逐时刻的最近描述，而不是固定追踪一条 P。没有跨时刻路径连续性惩罚，也没有把前一时刻选中的 P 强制延续到下一时刻，所以同一个回放方向在相邻时刻允许切换到另一条最近 P。

## 容差和权重的来源

`score()` 中的 `.08`、`.12`、`.25`、`.18` 是脚本作者（本次 LLM agent）自行提出并编码的固定容差，没有来自样本统计、交叉验证、校准集或用户/主 agent 指定的依据。它们不是统计校准尺度。

实际执行核验（调用 `cards()` 和 `vec()`，取 `states_001.zh-CN.md` 第一张卡）得到 `len(vec)=47`，组成是 `cur_mom=3`、`fc_mom=3`、`cur_regions=15`、`fc_regions=15`、`rms=3`，即 22 个 current 几何值、22 个 forecast 几何值和 3 个 RMS 值。实际 RMS 位于向量索引 44、45、46；因此命中 `i < 44` 之后的 `.35` 分支，而不是 `.18` 分支。current 与 forecast 各占 22/47 的逐维平均贡献，RMS 占 3/47；并非严格先聚合后各占 50%。原 method 中“当前云与预测终点云各半权重”应理解为字段数量对称的描述，而不是代码中实现的严格两组半权重。

## 规则来源的澄清

原 method 中“规则由人工预先固定”表述不精确。实际情况是：这些字段选择、容差数值、绝对差平均和最近 P 决策，都是本次 LLM agent 自行提出并编码的规则；主 agent 和用户没有指定这些数值容差，也没有提供统计校准参数。程序随后按该冻结脚本自动完成排名和历史子状态回放。
