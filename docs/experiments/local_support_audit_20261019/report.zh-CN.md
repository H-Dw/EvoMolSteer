# 局部支持点数审计与 R02_v3 改进

日期：2026-10-19。本次完成本地代码修改、确定性真实数据分析、奖励编译及测试；未启动新 FLOWR 生成，未重新调用 Analyst/Designer。下述区域是待验证假设，不是已证明提高亲和力的新 checkpoint。

## 1. 20 点从哪里来

| 位置 | 原行为 | 处理 |
|---|---|---|
| `nc_guidance/search.py` | 特定阶段直接写 `max_local_points=20` | 改为读取该对照实际绑定的历史支持；不再假设其点数 |
| `nc_guidance/autoresearch.py` | 区域构造使用 `(8,12,16)` 和 `(8,12,16,20)` | 按必要邻居和声明上限枚举可行大小 |
| 同文件 nested_parent | 只允许8、12、16、20点，且未验证真包含关系 | 支持任意可行点数，必须是父区域的真实子集 |
| `ancestral_modes/bank.py` | 默认继承父程序区域，并构造等点数参考；缓存主要绑定银行文件 | 继承区域保留为历史对照；新增独立、受覆盖预算约束的测量区域 registry |
| 历史程序 / 配置 | 冻结了实际20点及 `max_local_points:20` | 保留以复现；它们是历史参数，不再作为新挖掘的默认目标 |
| 批次校验、bootstrap、轮数 | 20批、2000次bootstrap、20轮等 | 与原子点数无关，保留 |

奖励类本来就没有“必须等于20点”的判断。真正的问题是候选范围、区域继承和固定的大小集合。新流程没有把20替换成另一个固定目标数。

## 2. 新接口与策略

新增通用 `evomolsteer.local_support`：

- 根据教师原子总数、`max_fraction` 和可选 `max_points` 求交集上限。
- 严格校验实际槽位、范围、重复点及覆盖；预算不足时报错，不默默放宽。
- 上限不是需要填满的点数；可行的所有大小均可进入候选。
- 无新策略字段的冻结程序保持原数值语义。

本次分析配置位于 `configs/analysis/local_support_mining_20261019.json`：覆盖比例上限0.32，最少2点。对25原子教师，允许2–8点；对100原子教师，上限为32点。策略均来自配置，函数没有固定点数20或8。

新增 `evomolsteer.ancestral_modes.support_mining`，支持 `prepare` 与 `compile`。输入为教师bank、终态原子表、冻结分组表、口袋坐标和配置；输出为紧凑区域registry、统计证据、编译程序及绑定记录。

候选来源包括原子图邻域、按实际键长确定尺度的空间邻域，以及按分子比例提议的界面区域。化学角色只提供背景，不自动开启类型、氢键或能量奖励。候选可以不连续，也包含非极性的骨架区域。

## 3. 具体计算内容

终态对照使用源报告的 `quality_tail` 标签。它是该报告定义的高质量尾部，不冒充原Steer所有尝试的前5%、10%或20%。本例剔除教师自身及其整条root后，剩余60个高质量终态、860个其余已观测有效终态，来自22条root、19个来源批次；其余组不是灭绝分支，也不自动等于失败。

每个候选区域计算：

- 局部点位置误差；
- 区域内部成对距离误差；
- 区域相对口袋位点距离误差；
- 口袋坐标系下的有符号x/y/z偏差；
- 局部误差减整体误差，检查局部关联是否只是整体相似度的反映。

跨分子使用Hungarian几何配对，不把原子序号当作共享身份。先按root平衡均值，再以来源批次为bootstrap单位，保留同批SMC依赖；没有使用原子数、克隆数或时间点数充当独立重复。

对真实教师的当前态、同forward时刻端点预测，分别在完整学习窗口拟合变化曲线与时间变化率。它们是单路径演化，不作为群体富集或空间梯度。原有 `regional_evidence` 与 `forecast_evidence` 仍可为入选区域提供51个时刻的谱系/选择证据。

没有新增亲和力预测调用，没有拟合新的亲和力模型，也不保存逐候选展开特征表。54个区域的registry和统计约0.48 MB；只存支持、摘要、区间、曲线参数及来源指纹。

## 5. 如何真正进入Agent与推理

新增区域可通过 `local_support_registry` 接入祖先模式工作流，`local_support_policy` 必须与测量一致。仅在明确配置的 `local_support_phases` 中扩展选择；`local_support_operators` 列出允许的实际算子。不改变旧35轮实验或冻结结果。

Analyst获得 `local_support_evidence` 工具。新增查询轮保证这类测量不会被原有化学上下文查询挤掉；最终选择必须引用所选区域自己的测量。未获得相应证据的区域不能依靠另一段解释通过交接。

Designer选择注册选项后，确定性编译器绑定：

`region_id → atom_slots → operator → teacher representation / clock → actual_terms`。

`local_feature_binding` 提供这一链路。奖励构造再次检查覆盖上限；自由文本不能偷偷加点或回退到宽参考区域。

已经完成 `[5,8,11]` 的三种编译验证：

1. `pointwise`：控制局部预测点的位置；
2. `pair_distance`：控制区域内部距离，局部整体平移/旋转不直接受此项惩罚；
3. `pocket_distance`：控制该区域相对口袋的位置。

三者保留R02的端点预测时钟、0.1–0.5窗口、100步及原剂量。成对/口袋距离容差来自实际局部键长与配置比例。示例是确定性接口验证，不是新的LLM设计决定；旧Analyst/Designer哈希不会冒充新设计来源。

编译文件在 `compiled/`。绑定文件指向已有教师bank，不复制大体积轨迹，也不启动模型。真实LLM API入口仍保留 `deepseek-flash`；本机本轮没有可用的 `DEEPSEEK_API_KEY`，因此没有把程序测试冒充真实API或生成效果验证。

推理日志新增直接支持点数、覆盖率、支持内注入RMS、支持外注入RMS。缩小区域可能把同样的全分子RMS预算集中到少数原子，需用这些读数校准，不能仅保持0.66就宣称剂量完全可比。日志新增不改变旧注入公式。

## 6. R02_v3后续顺序实验

1. **先比较支持。** 冻结R02时钟、奖励类型与窗口，对比旧20点、3点/5点骨架候选、N22三点区域及等大小的其它区域。先记录实际局部位移；另做剂量匹配，不把选区和加大强度同时优化。
2. **再比较observable。** 固定选中的小区域，分别比较逐点位置、内部距离、口袋相对距离，避免直接把三个项全部打开。局部构型与在口袋中的摆放分开检验。
3. **再比较时间策略。** 使用同刻端点预测作为R02基线，再对照同刻实际祖先和有限前瞻桥接；学习与控制范围动态读取。时间曲线先用于查找阶段性不足，不能把时间斜率当作空间力。
4. **形成—保持—价值分开。** 核查0.5时局部目标是否形成、0.5–1是否保持、最终pIC50与合格高分数量是否提高。只形成不增益，就修改优势特征假设；不一律加强权重。
5. **最后测试局部区域互补和多教师适配。** 单项有真实增益后才组合非连续区域，所有直接支持按并集核验；不先扩大回大部分分子。

生成验证采用相同B50、初始张量和逐步随机输入，额外以新随机输入确认；无SMC、无affinity-head梯度、不限制自由化学图变化。最终报告整体及冻结优质路径子集的平均、分位数、最高亲和力、高分合格数量、失败与应变。该部分是后续实验方案，本次没有执行。

## 7. 复用命令

仓库根目录中设置 `PYTHONPATH=src`，运行：

```powershell
python -m evomolsteer.ancestral_modes.support_mining prepare `
  --bank docs/experiments/ancestral_modes35_v3_20261016/bank.json `
  --atoms <终态原子表.csv.gz> --membership <冻结分组.csv> `
  --pocket <口袋原子表.csv> `
  --config configs/analysis/local_support_mining_20261019.json `
  --template F_b011_s030_native --output <新结果目录>

python -m evomolsteer.ancestral_modes.support_mining compile `
  --bank docs/experiments/ancestral_modes35_v3_20261016/bank.json `
  --registry docs/experiments/local_support_audit_20261019/mining `
  --parent docs/experiments/ancestral_modes35_v3_20261016/R02_v3/candidates/registered/programs/R02_v3.json `
  --region F_b011_s030__local_8d820f848732 --operator pair_distance `
  --program-id <新程序ID> --output <程序.json>
```

原子表需含node_id、atom_index、x_A/y_A/z_A；分组表需含唯一node_id、root_id、明确布尔高质量标签，推荐同时提供batch用于批次bootstrap；口袋表需含坐标、residue、atom_name、pocket_index。当前整体误差对照要求同原子数层或候选至少有教师数量的点，数量不兼容时明确报错，先分层，不能静默丢弃候选。

缓存绑定输入、实际支持、时间窗口、空间尺度、坐标转换、实现与库版本；改变定义后使用新版本结果目录。重复使用同一输入会校验产物，不重算、不重存原始结构。
