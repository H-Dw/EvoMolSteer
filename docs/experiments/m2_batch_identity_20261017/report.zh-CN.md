第三组与固定组的 job 在去除 name、n、batches 这些任务范围标识后完全相同；实际两个组均为400，模型权重加载入口也相同。

已核验的共同设置：同一 M2 program 文件（SHA-256 91fd96a203e1…）、同一静态教师文件（b6e61ec5cb8b…）、同一 target 输入路径、flowr_root_v2.ckpt（worker 强制校验 f28e863b2b20…）、master seed=42、indexed_batch、B50、100步、前50次更新引导至状态.5，之后原生完成至1、rho=.33、τ=.5、4个邻近教师、无SMC。动态状态不同使绝对注入位移略有差异，但两组实测注入/校准比例均约.33，未发现第三组额外加大权重。

第三组代码提交 ce85fde5c5ef，固定组为40c7fff4e3f4；提交号不同，但本次核验的启动worker、wrapper、dependency controller、通用controller、batch生成、endpoint与affinity geometry reward七个源码 Git blob完全相同。评分源码SHA也相同。不能仅凭提交号差异推定奖励改变；此核验不等于新增完整环境下的精确重放。

实际随机种子按 `42+100003×batch_index` 派生，batch6238为623818756。batch_index不是无关文件名：它决定不同的初始坐标/类别随机输入和后续随机流。不能仅将其它任务的 master seed 写42就声称复用高分样本的条件。B也必须保持50，截取一个slot或换B会改变随机数消耗。

batch6238自身均值只有7.640541，而同组batch6234均值7.806106、Best8.141102。因此该批并非整体更容易，也没有证据指向特殊隐藏调参。观察符合稀少高分路径随随机输入/后缀变化，但要准确区分初态与后缀的贡献，需要额外反事实重放。

S3和Top10等后续实验比较的是6376–6383固定输入，其相对**同池M2**的差异是有效的局部比较；不能据其Best低于历史8.8816就认定总体极值能力更弱。local/祖先等研究若输入池、B或原生协议也不同，跨池Best更不能作配对因果判断。反之，也不能凭样本池不同就推断这些方法一定能复现或超越8.8816。

固定组选择依据是已授权的“复用已完成400+400”策略，明确选当时最近完成且保留结构的任务组，而非根据affinity/strain选池。历史3000与该组分别保留。后续报表应同时列“本池M2”“历史M2极值”，避免将同名M2的不同样本范围混淆。
