## 为什么单个模块需要一小时以上

每个独立确认使用 8 个新的 RNG batch，每批 50 个分子，固定主种子 42、100 个积分步，沿用既定 `indexed_batch` 派生种子。M2 与无引导各 400 个样本。如果 Analyst/Designer 输出新数值程序，再生成该程序的 400 个样本。六条角色链在奖励数值等价时共享分子生成结果，未逐链重复生成六遍。

| 生成模式 | 已计时批次 | 平均 s/50 分子 | 8 批约需 |
|---|---:|---:|---:|
| 无引导 | 64 | 205.76 | 27.43 min |
| M2 | 64 | 259.01 | 34.53 min |
| 当前时间混合候选 | 44 | 262.92 | 35.06 min |

800 个对照样本仅批次计算就约 61.97 min；加 400 个候选则约 97.02 min，再加 API、本地评估和交接，得到表中约 70–115 min。M2 比无引导平均多 53.25 s/批，约 25.9%；该差额还包含奖励、保护检查和更长的引导日志，不能全部归为 backward。

这不是 API 等待或生成越来越慢。已结束 M2 批次约 250–278 s，无引导约 198–220 s，当前批次处于相同量级。

## 源码定位与潜在优化

1. **每步仍有两个完整口袋前向。** 上游 `_generate_selective` 每步运行 target 与 untarget；`gradient_source` 只替换 target 块，保留完整 untarget 块。当前适配器关闭 SMC，untarget 被明确声明为诊断而非目标，但仍计算 100 步。因此无引导约 200 次完整前向/批，M2 在其中 50 步额外回传坐标 VJP。这里是完整骨干前向，不只是轻量 affinity head。`extra_production_forwards_per_step=0` 表示没有新增 target 前向，不意味着每步只有一个总模型前向。终态重评分还另有模型调用。

   优先候选：为单目标、无 SMC 模式增加只计算 target 的入口，并在终态保留 off-target 评分。需要验证 target 轨迹、类别与 RNG 完全一致；中间 off-target 标签应声明未采集，不能填造。当前冻结消融队列没有改变这一行为。

2. **逐模块重新生成对照是大成本。** 数值去重范围包含 batch 列表；不同模块使用不同的独立确认 batch，因此仍重复生成相同 M2/无引导程序。这保持了前瞻独立确认，但 A3.1、D1.1 等两侧输出都落回同一数值程序时仍耗费约一小时。

   下一版协议可以预先生成公共配对对照池；对于完全相同的冻结程序，只报告“本次角色输出没有改变执行函数”，复用既有 M2/无引导结果，并继续测试角色输出功能。不能将这个相同程序结果宣称为该科学模块无效；跨模块共享数据也必须在统计中保留依赖。不能中途悄悄替换本轮独立确认策略。

3. **模型加载不是主要瓶颈。** 一次 cohort 加载一次 checkpoint，随后遍历全部 batch/arms，并非每批重载。14 个已结束 cohort 的“初始化/源校验/归档等循环外总耗时”合计约 10.45 min，每个约 39–51 s，只占全程很小部分；该区间没有单独分离模型加载和打包。

4. **记录存在可以消除的重复 I/O。** `EndpointCoordinateExtension.after_native` 追加引导记录，随后 `FlowCompatibilityExtension.after_native` 与 V2 各读取并重写整份 JSONL，一步两次全文件重写，随步数形成二次增长。每步 HDF5 又压缩、验证、更新 journal，最终再合并验证。应考虑先在内存组装完整一行，单次 append；每步仍保存校验和与失败信息。当前 CPU 利用率较低且设备繁忙，无法据此断言 I/O 已是主要瓶颈。采集到的终态 HDF5 打包验证约 1.7–1.8 s/批，未包括所有每步写入。

5. **本地质量评估可并行化，但收益有限。** 终态 MMFF/几何计算使用 2 个工作线程；PoseBusters 逐分子串行，之后坐标诊断约 1.4–3.6 s/cohort。已测 800 样本的 archive/audit/MMFF/PB 阶段约 178–447 s，400 样本约 92–219 s。这些时间仍混合了多项任务；不能分别声称 MMFF、PB 的精确占比。批量 PB 必须维持全部尝试与原 slot 对应，包括失败。

6. **网络不是主要限速步骤。** 完成到进入本地评估间隔约 8–61 s/cohort，14 次合计 6.97 min。这包含 20 s 轮询、连接、下载，不是纯下载时间。不能因日志更新间隔把持续计算误报成卡住。

保持模块串行，不等于所有独立批次必须串行。将来若确认能获得多张专用设备，可在同一模块、同一冻结 commit 下并行独立 batch，保留 seed 和配对；目前设备工具只返回一张可见卡，没有自动占用其它任务的物理 GPU。任务下一步能否选择新奖励依赖前一模块结果，不适合直接并行各消融模块。
