# M2 Skills 消融计划与实际执行的一致性审计

审计日期：2026-10-11。远端只读复核时间：16:17（北京时间）。

结论：**温度 0.5→0.25 是原计划允许的 Designer 候选输出，并非新增的温度消融条件；原计划文件未被覆盖，但执行器对后续阶段的依赖作了实质调整。当前只完成部分基线，不是完成了模块消融。**

## 1. 温度候选从何而来

原计划 `plan.zh-CN.md:108` 和 `protocol.json` 的 `lanes.G.prospective_allowed_changes.mixture_temperature` 已列出 `{0.25, 0.5, 1}`。D2 模块允许依据几何尺度选择核、曲率、温度或区域响应。G 通道每次只允许一个原子性几何修改，剂量与教师数据源固定。

实际来源链为：

`P_struct / chain_01` 的真实 DeepSeek Analyst 输出 → 同条件 Designer 输出 → `compiler.json` → 生效程序 `2c1474aed854…` → 远端 `DSF_2c1474aed854_b137_g` → 本地评估。

Designer 明确返回 `decision=edit`、`edit={parameter: mixture_temperature, value: 0.25}`。调用回执请求与返回模型均为 `deepseek-flash`，provider request ID 为 `d9c6784b-949f-4d79-a913-a37246656881`。请求、响应、编译程序与回执的 SHA256 均匹配。与冻结 M2 比较，排除标识、注释及已知不生效字段后，**唯一数值变化就是混合温度 0.5→0.25**。

因此它应命名为 **“P_struct 第 2 条角色链产生的温度候选”**。它不是 `D_drop_D2`、`D_alt_D2`，也不能据此断言 D2 有益或有害。同一完整指引的另外三条已完成角色链均选择保留 M2，复用同一生成结果；没有重复生成或伪造独立分子样本。

程序合法不等于奖励理由正确。该 Designer 把分子内部的 pair-kernel 距离壳层与教师之间的混合关系联系起来，缺乏直接数学依据：混合温度控制不同教师梯度的相对混合，M2 并没有独立的 pair-kernel 奖励项。此前的实际特征响应检查也未支持它所预测的壳层变化方向。

## 2. 哪些文件与调用保持一致

对原计划 `artifact_manifest.json` 的全部 9 个条目逐字节计算 SHA256：条件矩阵、共享契约、指引清单、模块注册表、计划、协议、功能评分规则和两份 Skills 草案全部匹配。冻结 M2 程序及教师引用也匹配原协议校验值；实际调用使用的模块注册表与原计划完全相同。

已完成的 8 份角色输出逐一核验：

- 请求和响应均匹配各自 API 回执的校验值。
- 实际交付的 system 指令匹配记录文本及冻结模块组装结果。
- 实际交付的证据数据匹配冻结证据包。
- 原始响应契约校验通过；请求和返回模型均为 `deepseek-flash`。
- 四份编译回执均匹配 Designer 输出、程序、教师引用及生效签名。

这些结果支持“原计划和已完成调用没有出现校验值不一致的改写”，不能用来证明全部科学解释正确，也不能据此声称运行设计完全符合原计划。

`activation.json` 已把上述部分选择写入 `protocol_amendments`，但**写入变更记录不等于用户批准变更**。其中把完整 Analyst 池称为“preregistered”不能覆盖原计划明确的“先选 A* 再冻结”要求。这是执行实现对原方案作出的调整，需要纠正，不能以原始文件校验值没变来掩盖。

原条件矩阵 46 行：P0=7、P1=10、P2=12、P3=17。激活文件 27 行：P0=7、P1=9、P2=11。激活行的字段与原矩阵相比，仅模型与排队状态改变；**关键依赖却在 activation 的文字策略及执行代码中变了，而不是在条件行中体现**。因此只比对 CSV 不足以检查方案完整性。

## 5. 恢复实验前应遵循的路径

当前结果保留为**未完成的 P0 基线筛查**，不要改名成逐模块消融。冻结 M2 和历史 Steer 保持原身份；温度候选不晋升为新默认。

后续应以原 46 行矩阵为主表，仅继承用户明确要求的真实 API / deepseek-flash 替换；协议与实施文件的区别必须可追溯。先完成同接口的 P0 基线与 P1 Analyst 筛查、功能验证及选择关卡，再依据选定 A* 冻结六份响应。Designer G 消融读取同一冻结池，U 消融读取明确选定的 G 形状。补齐标量 no-op 对照，按原计划进行后续精简和条件性必要性复核。

如果采用修复后的接口版本，应另建一致接口的角色基线并保留旧记录；不能混合旧缓存与新调用后声称全部角色使用同一接口。符合共同配置与初态的分子控制结果仍可复用，角色链身份不能伪造。

执行器还应在阶段切换前验证：选择与冻结凭据、上游条件完成情况、冻结池校验值、G 形状来源、条件别名、已完成的功能审核。缺少前置条件时停止，不能自动用 P_struct 或 M2 替代。角色输出、参数候选、生成任务必须分别显示，避免把 LLM 的合法输出误读为新增的消融模块。

本次审计只增加只读审计工具、结果和报告；没有修改原计划或 Skills，没有调用 LLM、恢复队列、启动推理或删除结果。
