# M2 基准上的 Analyst → Designer 模块消融计划

日期：2026-10-11。状态：**仅规划，未启动实验**。本目录保存规划、指引草案和验收标准，不覆盖活动 Skills、不生成任务队列、不调用 subagent/API、不连接远端、不运行 FLOWR，也不清理已有结果。

本计划要检验的是：某条指引是否提供了模型本来不会稳定给出的有用信息；该信息是否进入奖励设计并改变实际坐标控制；改变是否改善最终预测亲和力并维持构象质量。文字出现、程序字段改变、奖励上升，分别不能替代后续三个层面的验证。

## 1. 基准与历史证据

M2 是冻结的**数值奖励/推理配置**，不是一次新的 Analyst/Designer 调用，也不是新训练的模型权重。原 FLOWR 模型仍使用历史相同权重。基准程序为 `configs/experiments/steer_dependency_v1/D2_without_trajectory_static.json`，SHA256 为 `91fd96a203e1d4138378fecb01e11d433cd6d9e7b8455da036a70c713c4999b6`；引用为 `configs/experiments/steer_dependency_v1/static.json.gz`，SHA256 为 `b6e61ec5cb8b528e3696fcb73982a83af8bc67f5be04fe427ad1c580c5baa485`。两个本地文件已按历史任务声明核对。

M2 在整个学习窗口使用最后记录的 score_time=0.49 的 28 个预测端点教师，每步选择最近四个；教师评分加权 beta=0。它没有使用最终解码后评分最高的单个分子。学习/引导窗口从引用元信息读取，当前为 [0,0.5]；100 个积分步，50 次控制后继续原生推理至 1。实际 pointcloud 曲率参数缺省为 1 Å，文件中的 legacy `robust_delta=2` 并非这个函数的实际曲率；`geometry_block_weights` 也不驱动 pointcloud 力。新实验必须防止这些无效字段再次成为“已优化参数”。

历史 M2 两批共 100 个样本：平均预测 pIC50=7.74466，PB fast=100/100，应变中位数/重原子=0.48134，应变 P90=0.72849。相同批次无引导均值为 7.48952。历史 Steer 的 1000 个尝试均值为 7.65148、P95=8.23844；不同计算预算的历史 Steer 只作参照，不用于提示词消融的成对因果检验。M2 尚未完成本计划的独立确认。

### 2.3 原 dependency 入口

Analyst 基础文段要求读取 manifest、提出有证据的坐标假设、说明可用观测/反例/限制，不能从受体结构凭空推断富集或生存趋势。其追加块分别是谱系和时序。

Designer 基础文段要求选择注册的可微奖励或 defer，说明目标来源，区别统计支持与几何代理，使用真实 FLOWR endpoint VJP、detached correspondence，区别时间导数与空间梯度，并提醒整体倍数可能被梯度归一化抵消。其追加块分别是多模态构象和父子增量匹配。

兼容入口 `continuous-analyst`、`coordinate-analyst`、`coordinate-designer`、`affinity-endpoint-pullback` 目前路由到通用两个角色，不是额外独立模块。`flow-compatibility` 等专项 Skills 不自动叠加；若加载相同建议会使文字删除失效。新规划只加载本目录草案及外置契约。

## 3. 外置固定契约与可消融模块

**执行/数据正确性不是生成研究指引的消融对象。** 模型路径、表示、标签含义、学习支持、统计单位、JSON 格式、无 affinity-head 导数、无新 SMC、自由化学图、有限参数及哈希校验移入 `contracts/shared_contract.md` 和确定性接口。这些约束不会在某条件被删除；否则测到的是算法被破坏的效果。

Skills 只保留下面八个待证研究模块。目标、具体残基/坐标、时刻、数值阈值、模型选择及环境配置均不写入 Skills。每个模块的原文只有一个段落，便于准确删除或替换。草案尚未加载到活动 workflow。

### 3.1 Analyst 候选模块

|ID|功能|应在输出中出现的信息|修改方向的条件|
|---|---|---|---|
|A1 选择对比|从优势/失败对照找到与目标优化相关的坐标差异|真实 cohort/label 语义、效应方向、对照及 evidence ID；区分绝对形态与优势富集|只按绝对几何描述的突出程度排序，不优先高低分对比|
|A2 可靠性与反证|可靠性进入方向优先级，而非只附在免责声明中|强效应但弱支持与较小稳健效应的区分；跨批支持和相反证据改变排序|按点估计幅度排序，不让区间/q/覆盖改变优先级，但仍如实说明它们|
|A3 空间分配|判断优势是整体位置/形状还是可局部强调的区域|区域 evidence/空间范围、与全局运动的区别、保留周围区域的理由；没有区域证据时明确全局方案|优先整体构象/形状，不提出局部强调|

没有强制要求每次都找到“优势区域”，也不要求推断不存在的能量或神经模块因果关系。输入不足而拒绝某种假设，是正确响应，不计为指引失效。

### 3.2 Designer 候选模块

|ID|功能|应在输出/程序中出现的信息|修改方向的条件|
|---|---|---|---|
|D1 证据到项|把 Analyst 的方向映射到一个适用的注册奖励修改|引用具体 hypothesis/evidence、指出实际改变的距离/区域/核响应及预期诊断|优先通用整体匹配，对比证据仅作说明，不决定奖励项|

|D4 基准与反例|判断一个改变是否值得采用|对 incumbent 的预期优势、反例、明确失败条件；允许 retain/defer|即使证据不能区分方案也优先选择一个合法的探索修改|

删除 D3 不能删除 FLOWR Jacobian 或修改归一化器；删除 D1 不能放开非法函数；删除 D4 也不能故意降低亲和力。修改方向必须是合理竞争策略，不能通过反转总目标来人为证明模块有用。

## 4. 先建立能够传递指引的接口

输入证据在任何调用前冻结：静态教师引用一次保存，配套 0–0.5 坐标统计保留优势及失败对照、效应/CI/q、跨批支持、全窗口积分与趋势摘要、拟合误差及空间区域映射。禁止每个条件只给“最强八条”；不能因删除文字而删除数据。超出窗口的几何不进入学习。末次联合 head 标签与最终解码重评分严格分开；真实终态信用缺失时不启用那个研究分支。

使用相同版本的预设工具产生简明结果并提供 receipts。Agent 可以查询预注册的证据切片，但不会任意重新定义 cohorts 或统计单位。无历史对照的原始配体/受体几何只能提供结构假设。富集、差异、趋势计算的数学定义不作为某条件的可变因素。

### 4.1 奖励形状通道 G

所有条件从同一 M2 程序和教师库出发；固定 eta=.33、ramp=0，固定教师评分 beta=0。允许的**候选**旋钮是教师邻居数 2/4/8、距离先验温度 2/4/8 Å²、混合温度 .25/.5/1、实际 pointcloud 曲率 .5/1/2 Å，以及空间强调接口。

空间强调使用现有 `RegionalPointReward` 的软区域注意力方案作为实现参考；区域从已提供 evidence 索引，保留正的周围区域权重，不设图/类型 gate。候选 radius、background、稀疏权重网格在实施前按数据尺度冻结。该类虽然已有实现，但**新实验的绑定/编译接口、M2 等价回退及模块读数仍需实现和验证**；不能把本规划表当作已可运行的注册表。

在 G 通道，每次设计至多选择一组预定义、原子性的几何修改，例如一个 region-emphasis recipe；不能再改变剂量或教师数据源。先只使用固定教师集合，不新增 contact/energy 项、不强制动态教师、不复制历史速度。时间趋势可供解释，但主实验不把它自动转成时间变化奖励。

### 4.2 剂量通道 U

锁定已选定的 G 奖励形状，允许 eta=.20/.33/.50 或 ramp=0/1/2 的一个原子修改；不能同时改核或空间目标。D3 的性能消融仅在 U 通道进行，否则固定剂量会把模块效果堵住。

增加整体奖励乘以正标量的 no-op 控制，验证归一化后的力和轨迹不变。需要比较的是实际 RMS、控制覆盖、梯度方向及 cap/backtrack 激活，不是配置数字或 raw gradient norm。

### 4.3 因果链审计

1. 精确记录渲染后的 system/user messages、源块范围和内容哈希；删除块不能出现在其他 Skill、schema、例子、工具说明或 task 中。
2. 模块输出按事先定义的功能 rubric 盲评，并核对引用、数值、对照语义和工具 receipts，不能只做关键词计数。
3. 确认 Analyst 的真实响应逐字进入对应 Designer 请求；不以手写答案替代。
4. 确认 Designer 的合法修改进入具体 reward factory，读取的是实际生效字段。
5. 在冻结的既有状态探针上检查条件奖励导数、归一化方向/剂量及模块特异读数。可执行配置不同仍可能数值等价。
6. 实际 FLOWR 检查唯一生产 forward、真实 VJP、无粒子重采样、窗口后零注入，记录 .5 状态与终态。此后才评估亲和力与应变。

模块存在但功能不出现：先查缺失输入、重复/冲突指令和接口，再修复并将受影响对照全部重做。模块删除后模型仍自然完成目标功能：视为该指令可能冗余，不能自动解释成配置失败。分析变了但奖励不变：记为下游瓶颈；不能宣称模块改善生成。

## 5. 分阶段实验顺序

### P0：建立 GPT-5.6 Luna 同模型基线

数值 F0=M2、N0=无引导与 Agent 无关；在所有新批次作共同控制。以下五个提示词方案都使用 GPT-5.6 Luna 和同一证据/注册表：

- P_current：当前通用 Analyst/Designer 原文。
- P_dependency：旧 I0 的实际角色原文，含四个追加模块；仅作旧实验流程诊断。
- P_clean：外置契约+最小角色说明，移除旧八扩展及四追加研究指引。
- P_flat：新 A1–A4/D1–D4 的相同文字，不加模块标题。
- P_struct：相同新文字，按模块标记结构化。

P_flat/P_struct 用于隔离组织方式，P_clean/P_struct 用于判断新指引是否增加价值。新旧模型之间不做单句效果归因。每个 Agent 方案先完成六个独立角色链：两种保持意义的 task 表述，每种三次空白上下文调用；模块原文不随表述改变。候选优劣必须按角色链平均效果评估，不能只选一次最好的 Designer 输出。

结构化全模块方案若没有维持 F0 performance，不晋升为默认。仍可按预注册的单模块删除诊断失败原因；失败方案不会替换冻结 M2。若所有合法程序与 F0 等价，应报告“尚无增量”，然后检查接口能力，不能虚构新分子实验。

### P1：先 Analyst 消融

Designer 的文字、注册表和执行通道固定为 D0-G；所有随机调用规则相同。对 A1/A2/A3/A4 依次比较 full、drop、alternative，并加 Analyst 全研究模块关闭的 A_empty。每个条件六次独立 Analyst 调用；每个输出进入一次全新且提示词固定的 Designer 调用。改动一个 Analyst 模块，其他信息/指引完全相同。

每组先验证对应分析功能，再按数值有效设计比较生成。Designer 的固有变异属于整个中介链的噪声，六次重复不能被当成完全可控的 token 随机种子；边界候选再做第二次固定 Designer 重放检查稳定性。并行只允许用于无关计算，条件探索和版本晋升仍顺序进行。

先按同一个 full base 测完四个模块，以识别交互，再依次剔除无增益/负面/等价模块。每次删除后形成新的 Analyst base；其余拟保留模块必须在新 base 下重新敲除验证。不能假定在原 full 中的必要性在简化后仍成立。

### P2：再 Designer 消融

Analyst 选定后冻结 A*，生成六份不含任何生成评估结果的 Analyst 响应组成固定输入池。每个 Designer 条件读取**完全相同的六份响应**，不能挑一个“最有利”的 Analyst 答案。

- G 通道：分别测试 D1、D2、D4 的 full/drop/alternative，加 D_empty。几何通道的剂量固定。
- U 通道：固定 G 的奖励形状，测试 D3 full/drop/alternative，加整体倍数 no-op。
- 所有条件由独立 GPT-5.6 Luna Designer 生成真实响应，不手动代写奖励参数。

逐个剔除无增益模块。改变方向若优于原模块，就把更优方向作为新候选并重做，而不是认定原模块必须保留。只有“替代方向差但删除不差”，不足以证明原指引有必要。

### P3：共同必要性与最终验证

把 A*、D* 及已选定的形状/剂量合并；先在全新批次比较组合方案与 F0、N0，再从最终方案中逐个删除或替换每个剩余模块。早期 base 的替代方向结果不能代替最终上下文的替代测试。只有最终上下文中的必要性被确认，才进入默认研究 Skills。对因角色重复输出提示可能存在冗余的模块对，补充联合删除；对出现反向影响的模块，补充 2×2 交互，确认后删除较弱或冗余指令。

若没有任何研究模块通过必要性标准，允许最终为“简短角色接口+冻结 M2 算法”，并报告没有证明 LLM 指引带来额外收益。不会为了证明 Skills 有用而强迫加入模块。

## 6. 评估与保留规则

### 6.1 三类不同的成功

- 功能成功：模块在有足够输入时完成真实的分析/设计任务，引用、方向、来源和单位正确；正常模块六次中至少五次满足 rubric，替代模块六次中至少四次体现其竞争策略。无支持而拒绝推断可计正确。
- 传递成功：分析信息被 Designer 使用，生效程序和模块特异控制读数改变；轨迹差异不能仅由算术漂移解释。已等价程序共享生成并单列角色重复次数。
- 性能成功：独立确认中预测亲和力或次级质量达到预注册标准。前两类成功不能自动获得保留资格。

功能门槛是工作流合格标准，不是统计显著性结论。若没有功能响应先修复该层，不开展用来证明优劣的大规模生成。还要比较 full/drop/alternative 在该模块特定的排序、区域、目标或参数决策上的差异；若只改变其他内容，不能宣称已验证预期作用机制。若删除后该功能仍稳定自然出现，应检验指令是否冗余，而不是强迫 Agent 不完成它。

### 6.2 主要与次级指标

主指标沿用相同终态评分流程：全部生成尝试的平均 FLOWR 预测 target pIC50；说明无法评分的覆盖和失败，不静默删样本或用成功样本均值替换主指标。有效样本均值另报。

次级报告 PB fast/有效率、收敛 MMFF 应变解除量/重原子中位数及 P90、收敛覆盖、有效唯一化学图、固定高分阈值产率、P95、唯一高分图。原子类型/化学图可自由变化，图变化本身不是失败。

阈值从数据 manifest 冻结，历史已有高分阈值为 8.258901977539063，仅写入实验配置。不能使用本次候选自己的分位数定义“成功”。最高单个样本不是主指标，100 与 1000 样本最大值不直接判优。

### 6.3 统计设计

未来建议筛查四个独立批次，每批 50 个初始样本，即每个**不同数值程序** 200 次；初次确认八个新批次、400 次；最终必要性再用八个新批次。六条 Agent 链按相同生成批次/slot 配对，对角色链与生成批次做交叉分层重采样，给出实际差值区间。相同程序共享结果不增加分子样本量。

FLOWR master seed 固定 42，实际批种子沿用 `42+100003*b`。规划索引为 2000–2003（筛查）、2004–2011（确认）、2012–2019（最终）；实施前需确认未使用，否则在未看结果时重新冻结完整索引表。这是计划而非任务预订。subagent 没有保证可指定 token seed，不能声称 Agent 的六次输出也被 seed42 精确控制。

筛查仅用于选模块与估计功效，确认前按观察到的批次/角色方差冻结样本量和比较集合。不以 p>0.05 判断无效。每阶段 drop/alternative 对比统一做 Holm 假设检验校正；同时区间由实施前冻结的 max-T 或保守的 familywise 检验反演构建，不能把普通区间称为“Holm 调整区间”。对数据包中的关联统计沿用原有 q 定义，不重新把最强选中证据当完整检验集合。

确认不足时可按未看确认标签的功效估计使用预留批次；若采用结果驱动扩样，必须预先实现 alpha-spending 的分组序贯规则。默认方案不用边看结果边扩样。预算不足或区间过宽，标记未解决，不能宣布必要或等价。

### 6.4 必要性判定

以下阈值是本计划的前瞻选择，不是现有结果：

|结论|要求|
|---|---|
|结构化新基线维持 M2|成对平均差点估计不低于 0，调整后区间下界高于 -0.02 pIC50；PB 和应变满足质量包络；尚不能据此宣称提高|
|模块对亲和力必要|最终上下文中 full-drop 与 full-alternative 的调整后区间下界均超过 +0.05 pIC50，功能与传递成功，六条链中至少五条方向相同|
|模块对次级质量必要|亲和力差异的区间落入 ±0.02 等价区间，而删除和替代均明确使应变中位数或 P90 相对恶化超过 10%；标记次级必要，不能称为亲和力增益|
|可删除：数值冗余|完整有效奖励/归一化控制等价，或同条件实测轨迹等价；生成效果共享，不另造重复实验|
|可删除：性能等价|有足够功效的确认差值区间完全落入 ±0.02，次级质量也没有确定收益|
|应删除/改向|去掉或合理替代后确认亲和力更好，或原模块造成不可接受质量下降|
|未解决|区间跨越等价/明显下降界限；暂不列为已验证必要模块|

应变质量包络暂定相对 F0 中位数/P90 不增超过 10%，PB fast 不降超过 2 个百分点；这些只是候选准则，正式确认前按功效冻结。硬性无效、无法评分、能量计算不收敛均另外报告，不能通过删失败样本获得合格。最大值/高分尾部探索结论需要更大预注册样本量；本轮每程序 400 次确认并不保证能解析稀有尾部差异。

必要性结论限于这个 target、证据包、注册表和 GPT-5.6 Luna workflow。改变目标、公式库或工作流后必须重新验证。

## 7. Subagent 与数据存储安排

所有未来 Analyst、Designer 和需要的盲评角色显式调用 `gpt-5.6-luna`，使用 `fork_turns=none`，只提供该调用的请求包，不复用当前旧角色会话。模型设置写在 protocol/request/调用记录中，Skills 不包含模型或环境配置。调用端不允许默默回退 Sol、GPT6-Luna 或其他模型。外部 API 接口保留相同 schema；当前模拟不调用它。

给 Agent 的 condition ID 为随机化不透明标识；名字不包含 without/module/best，避免条件名变成信息权限暗示。模板、证据位置、task、schema 和 token 预算固定，除指定模块外相同。两种 task 表述不加入新的模块语义。LLM 不看到本轮生成的筛查/确认分数、排序或失败原因；后续改进是独立的新协议版本。

保存 request 的真实渲染哈希、实际调用模型、模块列表、工具 receipts、原始 JSON response、编译配置、数值等价证书、控制与质量汇总、简明决策理由。共享输入按哈希去重存储，不复制教师库和整份特征缓存到每个条件；保留可复算来源。设计记录保存证据—选择—参数—预测—实测，不要求模型私有思维链。

未来远端只执行锁定版本的 FLOWR 推理与精简结构记录；本地分析。每个条件独立目录；确认前删除的是本研究已经归档验证的临时轨迹，不涉及原始 Steer、M2/R26、旧报告或别的任务。只保留报告不能独立恢复逐节点信息，必要的原始轨迹/输入/谱系来源须继续保留。
