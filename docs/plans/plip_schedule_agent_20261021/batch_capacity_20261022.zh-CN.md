2026-10-22 用户要求暂停正式实验，教师改为原排名 Top1、Top2，先测量推理批量。
旧三教师目录、冻结配置、已提交结果和请求保留；定时任务保持 PAUSED，不自动恢复正式采样。
Top1 已完成全部 100 条 R0 和 R1–R4，共 400 次优化。Top2 尚未开始；Top3 排除。
新默认配置为两教师、200 条条件链、每版本 2,000 次决策，总计最多 4,200 条结果记录。

## 测试

运行 `scripts/benchmark_plip_batches.py --source-root <旧冻结目录> --output <新诊断目录>`。
脚本持有运行锁，使用原 v2 权重、两份 PLIP 模板、原始初态、完整 100 步和真实坐标梯度。
测量 20/40/60/80/100，每位教师每档两次；另有一次不计入统计的预热。
计时包含蛋白编码、推理、梯度、完整轨迹/checkpoint 写入和最终重评分，不包含 LLM、PLIP、PoseBusters。
报告同步后耗时、Torch 峰值 allocated/reserved 和设备级显存峰值；诊断不产生正式实验样本。
每个诊断结果先保存分数、校验摘要和载荷哈希，再清理结构载荷，保留所有 JSON 分析。

大批量由历史 20 槽位块拼接。容量探测使用第一批入口 RNG，仅作性能诊断；不能声称拼接后仍是原五条独立随机流。
batch=20 必须与已有 Top1 R0 的终态和 RNG 完全一致。所有档位须完成梯度、有限值、位移上限检查。
更大批量若要投入正式实验，还必须保持每个逻辑 batch 的 RNG，并验证恢复、类别转移、评分和输出归属。
显存容量通过不等于上述科学等价验收通过，不能直接修改旧目录的 `batch_size`。

## 进程管理方向

保持单一 GPU 推理所有者，LLM 请求使用独立的有界执行池；两教师批次交替进入就绪队列。
在一个教师等待 Agent 时，可以运行另一教师已经获得决策的 GPU 批次。
全局 LLM 并发上限仍为 4，不能两个教师各启动 4 个请求而无意翻倍。
每位教师独立维持完整 100 条链的轮次屏障和冻结总体统计；质量评价、最佳快照和清理提交后，才开放该批次的下一轮读取。
不允许两个线程同时修改共享模型的 `_adaptive` 或 integrator observer，也不在 GPU 工作进程等待网络时长期持有 GPU 执行权。

正式恢复前需给出两教师共用的容量/吞吐建议及随机一致性限制；本次测试结束后仍保持暂停。
