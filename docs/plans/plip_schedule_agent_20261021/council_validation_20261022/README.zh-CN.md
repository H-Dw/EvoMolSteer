## 当前实现

每位教师每轮有4组，每组100个候选共用一套四区间幅度。四个独立DeepSeek会话并发分析各自完整群体；
每组提出两个假设，第五个会话比较八个建议，选择四个不同调度并排序。下一轮仍为四组。
组内输入、历史和工具实例分别绑定本组；只可读取前轮已发布的公共反思，本轮其他组不可见。
汇总可选择同一来源组的两个建议，不要求四组各占一个名额。

独立保存 `reflection.md/json`、`published_memory.json`、`selection.json`，以及实际prompt、响应、工具、失败和哈希。
`MASTER_REVIEW_INPUTS.json`仅为供GPT主Agent全量复盘的证据索引，明确不表示已完成审阅或允许V2。
主Agent后续仍须覆盖全部教师、轮次、组内分析、汇总及未选中建议，才能修订通用skills。

`teacher_pipeline`通过两教师就绪队列调度单一GPU所有者。在A进入分析/CPU阶段后，已就绪的B可推理。
同轮全部质量评价及TOP1发布、清理完成后，才能让该教师下一轮入队。
测试已验证交错执行、共享HTTP并发上限4、提交屏障、失败保存和完成后不重复运行。
这属于调度器和适配器接口验证；正式400槽位混合父状态恢复、质量/清理事务仍需接入原生执行器。
当前不能宣称完整后台科学闭环已经运行，也不能用旧20槽位逐链runner代替新流程。

## 诊断建议及科学解释边界

汇总选出的四个调度为：

1. G3:H1：[0.5, 0.5, 0.5, 0.5]
2. G4:H2：[0.5, 0.6, 0.5, 0.6]
3. G3:H2：[0.6, 0.4, 0.5, 0.5]
4. G1:H2：[0.4, 0.5, 0.6, 0.5]

这些是功能验证的输出，不是已验证优胜策略，也没有启动其对应生成。
原始LLM反思原样保留，不能将其每一句话当作工具验证的事实。主Agent检查已发现：

- 有些文字把节点51／90／91的局部几何称为“final”；该诊断输入没有节点100局部几何，不能据此解释终态。
- 四组已生成不同调度结果；组内incumbent=latest的零差异只是缺少纵向历史，不表示组间差异为零或所有调度未测试。
- 输出中的SE、置信程度和具体未来pIC50增益区间没有相应已注册计算或纵向验证，不能作为统计结论。
- 该数据的随机流与原五批正式运行不同；不得将小幅组间均值差直接归因为调度。

因此本次确认的是并发、隔离、工具与汇总的数据流程；尚不证明反思可靠性或调度优化收益。
诊断反思留在operations下，不能作为正式优化历史自动导入。后续全量主Agent复盘须检查这些误读方向。
