## 分析与动作单位

旧代码对每个candidate调用一次LLM，每位教师每轮100次；各请求虽附带相同总体摘要，仍独立决策。
最新流程以“教师×轮次×假设组”为一个组内Agent会话，每组读取完整100候选及本组过去轮次的分析证据。
同一教师四组的四个会话并行执行，每组提出两个假设；四份结果完成后，再启动一个独立汇总会话。
汇总会话比较四组实测分布和最多八个候选假设，选择四个不同调度并排序，维持下一轮四组探索。
不要求每个组恰好入选一个；有证据时可从一组选择两个，另一组不选。
四个组内会话均不能读取当前其他三组的信息，包括工具结果和候选历史；工具实例绑定本组冻结证据。
前轮已公开的汇总反思可以共同读取。本轮反思在四组完成后才发布，仅下一轮组内Agent可见。
不再将100份完整轨迹直接复制进prompt：默认提供全组统计，LLM通过注册计算工具按需读取几何、时间区间、分群和具体案例。
一次会话可包含数次工具请求和最终决策，不等于保证只发生一次HTTP调用。

用户已确认：每个假设的100个候选共用一组四区间幅度，假设之间采用不同幅度或控制区间。
全部假设共享本轮开始时冻结的逐链TOP1父状态和100个候选身份，不能在一个假设完成后给后续假设换父状态。
每个组内Agent相对于本组已执行调度通常改变一个区间±0.1，最多两个区间。
需要两次连续、共同有效槽位Mean改善且有效数不下降的历史证据，才允许相应方向±0.2。
“探索程度不同”包括改变一个或两个区间，不允许因此任意放大幅度。原奖励函数、局部模板和位移上限不变。

首要目标为每个假设未经逐链择优的100候选Mean，Best其次。各假设需说明预期受益/受损群体、Mean贡献、Best潜力及可证伪条件。
每组自己的调度是其假设设计锚点；下一轮被选中的四个调度仍共享同一份已提交的逐链TOP1父结构。
分析来源和实际恢复父结构必须分别记录，不允许从已删除的原分析组分支恢复。
当父结构的历史调度不同，执行入口取所有候选中最早发生变化的区间，重算整个共同后缀。

## 工具而非LLM数值计算

`PopulationTools`为应用层注册工具，由现有DeepSeek JSON传输层发送工具目录并接收有schema的调用请求。
执行器只运行固定注册函数，不执行LLM生成的Python/shell，不接受模型提交的坐标、分数或任意文件路径作为真值。

| 注册工具 | 功能 |
|---|---|
| population_summary | 100次尝试的Mean、Best、Top10、分位数与有效数 |
| paired_comparison | 共同有效候选的差异分布、胜率及有效性转换 |
| geometry_diagnostics | 蛋白固定坐标系内局部RMS、距离、pseudo-Huber；不做刚体对齐 |
| interval_diagnostics | 各区间实际位移、裁剪、匹配切换与梯度/流方向关系 |
| subgroup_response | 按比较前分数固定四分位组，分析响应，避免按本轮结果分组 |
| candidate_history | 指定候选的全部试验、失败方向和历史假设 |
| history_summary | 全部固定轮次与逐链TOP1集合分开汇总 |

工具使用同一个不可变证据快照，每次调用保存参数、输入hash、输出和可引用evidence ID。
空间差异直接根据已保存的原生几何对应计算，原始逐步/节点文档仍保留；工具将冗余数值聚合后返回。
LLM输入包含工具schema，纳入保守输入预算；超限明确报错，不静默丢弃失败候选或低分候选。
单次会话默认最多4轮工具请求，每轮最多4个工具，再给出最终假设。所有请求和原始响应均保存。

## 假设数与显存验收

按用户最新要求依次测试8、4、3、2，首个两教师都能完成的档位成为默认假设数，每个假设100候选。
使用一个模型实例合并H个假设为物理batch=100H，避免H个进程重复加载模型。
这与并发H个独立GPU进程不同；两教师不同时占用两个模型实例。
已验证的batch100单假设峰值12.46 GiB不能直接证明batch800可用。
容量测试保留模型、模板、100步、真实梯度、checkpoint和重评分；诊断结果不计入科学样本。

8个假设已在真实batch800预热中OOM，失败记录保留；4个假设在两教师上均完成100步，默认假设数确定为4，不再测试3或2。
以`operations/hypothesis_wave_8432_dd942431/COMPLETE.json`及全部实际测量为准，CLI拒绝仅凭“完成标记存在”采用容量。
OOM前记录的峰值不包含申请失败的那块显存，不能把它当作800所需显存。

| 教师 | 同时假设数×每假设候选数 | 完整推理耗时 | allocated峰值 | reserved峰值 | 设备显存峰值 |
|---|---|---:|---:|---:|---:|
| Top1 | 4×100 | 178.99秒 | 37.44 GiB | 45.17 GiB | 45.69 GiB |
| Top2 | 4×100 | 180.18秒 | 37.45 GiB | 45.22 GiB | 45.78 GiB |

设备总显存约63.98 GiB，最小余量约18.20 GiB。此处每教师一个完整测量；8候选方向中的四个±0.1调度用于容量诊断，未调用LLM设计或计入正式结果。
相对依次执行4次batch100约205.06/206.01秒，合并执行的吞吐分别提高约14.6%/14.3%，耗时缩短约12.7%/12.5%。
计时包含checkpoint和重评分，不包含LLM、PLIP及PoseBusters；不能将GPU加速当成完整实验的同等加速。
两教师轮流使用单一GPU模型；一个教师的LLM/CPU分析可与另一个教师GPU生成交错，两教师各自4×100不同时进显存。
机器可读[容量证据](hypothesis_capacity_evidence_20261022/COMPLETE.json)随本地代码归档。

## 搜索预算与统计

采用4假设：每教师每轮400次尝试，两个教师每版本10轮共8,000次优化结果，V1+V2加共享R0最多16,200条终态记录。
每版本为80次组内会话和20次汇总会话，共100次逻辑会话；工具往返、格式修复和初始假设bootstrap另计。
组内共提出160个待选假设，汇总共选择80个；R10仍完成反思，但不因选出建议而自动执行R11。
首轮四个待测调度需要bootstrap记录；后续每轮使用上轮汇总的四个选择，不把未执行的建议计入科学结果。
V2仍复用同一R0、清空搜索历史，冻结版本内技能；复盘覆盖全部群体会话、工具输入输出、假设及数值结果。

同时报告：

- 每个假设的100候选分布，以及每轮各假设Mean/Best/Top10，保留全部失败和有效性变化。
- 每轮按整组Mean、其次Best选出的假设；明确它经过多假设选择。
- 每条原始候选链跨假设/跨轮次的TOP1集合，作为系统最终搜索输出。
- 同预算V2/V1比较，以及R0、历史Steer/Unguided参考。旧单假设优化只能作不同预算背景比较。

每轮四个假设全部完成评价后才更新逐链TOP1和群体历史。经校验发布最佳快照后，清理非最佳结构/张量，保留全部分析、PLIP/PoseBusters、prompt、响应及失败记录。
群体Mean最优的整个假设不额外保留100份结构；保留其分析文档。每链仍仅保留一个最佳结构，共100个，R0单独共享保留。

## 已提供的可执行入口与运行边界

最新四组分析入口：

```bash
python scripts/plip_group_council.py --manifest <四组证据目录>/manifest.json --output <本轮分析目录>
```

manifest的groups顺序为G1至G4，每项包含group_id、evidence、anchor_ticks，可另提供本组history文件。
100候选身份及顺序必须一致，当前四组属于同一教师同一轮；每组最新100条记录必须使用相同幅度。
四组证据、历史、技能与LLM配置按哈希冻结；输入变化不能覆盖已有会话。
汇总只能选择已提出的假设，不能修改幅度；选中四个调度必须不同。任一组分析失败则保留成功请求并停止汇总。
输出reflection.md/json为独立反思文档，published_memory.json注明可用轮次，selection.json记录四个优先级。
MASTER_REVIEW_INPUTS.json索引实际prompt、响应、工具和反思的哈希，明确reviewed_by_master=false。
每版本全部完成后仍需GPT主Agent覆盖审阅；不能用DeepSeek每轮汇总代替全量skills复盘或直接批准V2。

教师调度采用单一GPU所有者和两个教师的就绪队列。A在LLM/CPU阶段时，B就绪即可进入GPU；
A的当前轮全部质量评价、TOP1快照校验和清理提交完成后，才可将A下一轮放入队列。
两教师的HTTP请求共享并发上限4；两个4×100 GPU波次不同时运行。
调度状态保存于pipeline.json，已完成轮次恢复时不重复执行；失败保留原记录，拒绝隐式重置。
调度器已可注入推理/分析/提交适配器做交替运行，原生400槽位重启与存储适配尚未完成正式接入。

```bash
# 从暂停的旧工作中导出一个完整轮次，保留原文件不变
python scripts/plip_group_agent.py export --source-root <旧结果目录> \
  --teacher 5nn4_SC2_A_1017__top1 --observed-round 4 --output <诊断目录>/population.json

# 查看注册目录；增加--name与--arguments可直接调用同一计算工具
python scripts/plip_group_agent.py tools --evidence <诊断目录>/population.json --output <诊断目录>/tools

# 读取两教师真实容量验收，进行一个群体Agent会话
python scripts/plip_group_agent.py plan --evidence <诊断目录>/population.json \
  --capacity <旧结果目录>/operations/hypothesis_wave_8432_dd942431 \
  --output <诊断目录>/agent
```

新增群体规划器输出每个假设的共享幅度、100候选身份、共同父状态hash、恢复入口及证据引用。
它实际支持LLM→工具→证据→多假设闭环，但不会启动正式GPU采样，也不会调用旧逐链执行器伪装群体运行。
正式多假设GPU执行、混合父状态恢复、TOP1清理和完整报告流程仍需按100H布局接入并验收；本轮暂停期间不自动运行十轮实验。
